# src/server/jobs

The job system of B8. Every side effect is a row in `jobs` with an idempotency key; the Supabase Edge Function
`job-runner` runs `runOnce` once a minute from pg_cron, and heavy work goes to GitHub Actions and comes back
through the signed render callback. The jobs row is the truth; a pgmq message only wakes the runner.

Everything here is loaded by Deno as well as Node: imports carry the `.ts` extension, and nothing imports
a Worker module, a Node built-in or `env.ts` (R07).

| File                | What it holds                                                                                                                                                                                                                                                                                                                                                                               |
| ------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `types.ts`          | `StepDefinition`, `StepContext`, `StepResult`, `SystemJobDefinition`, `NonRetryableError` and the payload envelope `{ params, data }`.                                                                                                                                                                                                                                                      |
| `claim.ts`          | The only caller of `claim_job`, `finish_job`, `fail_job` and `requeue_job` (R26). Every change after a claim is fenced by the claim token.                                                                                                                                                                                                                                                  |
| `runner.ts`         | `runOnce(db, opts)`: the event sweep, the scheduler, the light queue in batches of 10, at most 3 heavy jobs, then the reaper. Each job is claimed right before it runs, under `AbortSignal.timeout`, and no job starts after 40 seconds. An unknown type waits 15 minutes at a time for a day; a Storage outage waits an hour; neither uses an attempt. A `run_local` job is never claimed. |
| `backoff.ts`        | `nextDelayMs`, the readable twin of the backoff `fail_job` applies.                                                                                                                                                                                                                                                                                                                         |
| `dispatch.ts`       | The GitHub adapter: one `workflow_dispatch` of `render.yml`, and the refusals that send a job to `dead`.                                                                                                                                                                                                                                                                                    |
| `reaper.ts`         | One `reap_stale_jobs()` per tick: expired leases fail, heavy jobs with no callback after 30 minutes fail, lost messages are sent again.                                                                                                                                                                                                                                                     |
| `scheduler.ts`      | `runDueSchedules`, a stub until B8b step 4.                                                                                                                                                                                                                                                                                                                                                 |
| `steps/index.ts`    | The step catalog and `getStep`. The self-test steps exist only when `MOP_ENV` is `development` or `preview`.                                                                                                                                                                                                                                                                                |
| `steps/selftest.ts` | `test.selftest_light` and `test.selftest_heavy`, with `params.fail` for the failure proofs.                                                                                                                                                                                                                                                                                                 |
| `steps/heavy.ts`    | `dispatchHeavy`, the run of every heavy step: the 65,535-character check, the dispatch, and `extra` kept in `jobs.result` for `onResult`.                                                                                                                                                                                                                                                   |
| `system/index.ts`   | The registry of system jobs (health, prune, reconcile, retention and the rest), empty until their steps land.                                                                                                                                                                                                                                                                               |
