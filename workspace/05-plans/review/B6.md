### E2E-02 · critical · Copying a request's photographs inside one Worker request exceeds the free plan's 50-subrequest cap at about 22 photographs
Lens: end-to-end · Touches: B3, B6, B7, B8

**Problem.** `createFromSubmission` (B7) and B6's `activate` run `copySubmissionPhotos` inside the admin HTTP request. Each photograph costs one Storage `copy` fetch and one `enqueueJob` RPC, on top of the actor read, the create or activate RPC and `fanoutEvent`. A request may carry 40 photographs, which needs about 84 outbound fetches. The Workers free plan allows 50 per invocation, so the request throws at about photograph 22. A retry repeats the copy call (an 'already exists' answer counts as copied) and the enqueue for every photograph already done, so it dies at the same point. Rows past the cut stay `staged` with no job. `enforce_publish_gate` checks only that the first photograph is rendered (G66), so the property can be published with part of its gallery missing. The public `POST submissions` signs up to 40 upload URLs in one request (Turnstile, rate limit and create, then 40 signings: about 44 to 45 fetches), which leaves almost no headroom. The 50 cap is written down nowhere in the project.

**Evidence.** B6 line 65: '`copySubmissionPhotos` calls B8's `enqueueJob(db, { type: "render_variants", ... })`' for each copied photograph, after `db.storage.from("submissions").copy(source_path, staging_path)` ('an "already exists" answer counts as copied'). G70 (3): 'B7's copySubmissionPhotos, the one copy routine used by createFromSubmission and B6's activate'. B3 line 86: '`submissions.create` calls `create_submission`, then for each returned media row calls `db.storage.from("submissions").createSignedUploadUrl(storage_path)`'. B3 line 133: '40 media entries pass and 41 are 422'. `grep -rn -i subrequest` over workspace/05-plans, 06-architecture, 02-tech-stack and GOTCHAS.md returns no line naming the cap, and P-009 does not list it.

**Do this.** Move the copy out of the request. `create_property_from_submission` and `activate_submission` call B8's `enqueue_job` in their own transaction for one light system job, `copy_submission_media` (`src/server/jobs/system/copy-submission-media.ts`, registered in `system/index.ts`, key `copy_submission_media:<property_id>`, data `{ property_id }`). The job runs in the Edge Function job runner, which has no 50-subrequest cap. Each run lists `staging/<property_id>/` once and copies the rows still missing an object, stopping before the runner's per-run time budget and returning `retry_at now` while rows remain. When it is done it requests one render for the property (E2E-08), not one per photograph. A copy error throws (normal backoff, screen 16). `copySubmissionPhotos` is deleted. The admin routes return `{ property_id, copy_job_id }`, screen 9 shows that job's state, and the screen 4 'Create property' retry becomes Retry on that job. Do not drop the copy in favour of pointing `staging_path` at `submission_media.storage_path`: `render_variants` deletes the staged object after rendering (G25), which would delete the request's original. On the public path, sign at most 20 uploads in `POST submissions` and return `upload_token` (HMAC over the submission id with the existing `CONFIRM_TOKEN_SECRET`-style pattern, 2-hour expiry). Add `POST /api/public/submissions/:id/uploads { media_ids, upload_token }`, which signs up to 20 more (rate-limited like the parent route, no Turnstile). Add 'Workers free: 50 outbound subrequests per invocation' to GOTCHAS P-009. Proof: `tests/unit/subrequest-budget.test.ts` wraps `fetch` with a counter, drives `createFromSubmission`, `activate` and `POST submissions` with 40 media, and asserts at most 35 outbound calls. Also `bunx vitest run --project db tests/db/admin.db.test.ts -t copy_submission_media` (create and activate each queue exactly one job). Watched-fail: put the per-photograph copy loop back in the service.

### DL-04 · major · Once accepted, a submission has no exit: withdrawn, unpaid or abandoned requests stay in Accepted, Awaiting Assets or Invoice Issued for ever
Lens: domain-logic · Touches: B2, B6, B7, B8

**Problem.** Declined is reachable only from `Under Review`. The agent can withdraw after acceptance, the house can sell before payment, the invoice can go unpaid, or the assets can never arrive.
