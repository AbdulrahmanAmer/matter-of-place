## Goal and observed exit
Every page carries one brand in its title, a unique description of a sane length, a self-referencing canonical, correct Open Graph and Twitter tags with an absolute image, and valid JSON-LD for its type; the sitemap, `llms.txt`, `llms-full.txt` and `robots.txt` are built from the database and are honest during coming-soon (S30); archive pages for cities, architects and styles exist only when at least three published properties justify them; mobile Lighthouse stays at or above 95 on the six key pages.
Observed exit (completion map B13): "rich-result test passes; llms.txt served; one brand in every title." Proof: `bun run scripts/check-seo.ts <url>` exits 0 for every route, `curl -s <url>/llms.txt` returns the file, and the external checks (Google Rich Results Test, Schema.org validator) are run once on a public preview by the owner. Honest caveat: Google shows rich results only for some types (breadcrumb, organization, article, video); `RealEstateListing` and `FAQPage` are valid Schema.org and useful to answer engines, but produce no rich result in the tool, so "passes" is defined for the types Google tests and by our validator for the rest.

Responses carry `x-mop-cache: hit|miss|stale|bypass` and `x-catalog-version`; if the database errors or is silent for 2 seconds the last good copy is served with `x-mop-cache: stale` (rule 7).
Invariants
1. One brand per title: routes pass bare titles; `pageHead` adds the suffix once (G-003, already fixed and enforced by `tests/unit/seo.test.ts`; this slice keeps that test green and adds cases).
2. One canonical per URL: absolute, `https`, apex host `matterofplace.com`, no query string, no fragment, no trailing slash except `/`. Filters and utm parameters never enter the canonical. `www` redirects to apex at Cloudflare (L1).
3. Thin pages stay out of the index. A market, region or `/properties` page with zero published properties is `noindex, follow` and absent from the sitemap while empty (ASSUMED, this follows S30: the coming-soon state is for visitors, not for search). The flag flips automatically when the first property is published because the head is computed from data: the decision is `indexable(count)` in `src/lib/seo.ts` (count 0 gives `robots: "noindex, follow"`, any other count gives none), called by the `head()` of `properties.tsx`, `$market.index.tsx` and `$market.$region.tsx` with the published count of that page's loader data, and `buildSitemap` uses the same function. Archive pages exist only when their count is 3 or more and the `archive_pages` flag is on (default false, seeded false by B3b's migration `20261001110000_coming_soon.sql`, switched on by an admin on screen 24, G18); below the threshold, or with the flag off, the URL returns 404 (`notFound()`), not a soft page, and the sitemap, `llms` files and `ArchiveLink` treat every facet as absent.
4. No invented facts anywhere in structured data: an absent field is omitted, never defaulted. No street address or coordinates for a property unless the row has a public address (ASSUMED: city level only, `geo` omitted, because owners are high-net-worth and exact location is the agent's to share). `offers` only when status is `Active`. Contact points only when `siteConfig.contact` has values. Nothing about price being merit.
5. Preview and non-production hosts are never indexed: every preview build and every `workers.dev` host (preview `pr-<n>.holy-meadow-4327.workers.dev` and the production Worker on `matter-of-place.holy-meadow-4327.workers.dev` until L1 attaches the domain, E2) gets `X-Robots-Tag: noindex, nofollow` on every response and a `Disallow: /` robots body. The decision is `isIndexableHost(host, env)` in `src/server/seo/robots.ts`, the one function both the robots route and B1b's pipeline call (B1b creates the file with this function and wires the pipeline to it; B13 adds `buildRobots` to the same file, G19): true only when `MOP_ENV` is `production` and the `Host` header (lower-cased, port stripped) does not end in `.workers.dev`. So every preview (`MOP_ENV=preview`) and the production Worker on its `workers.dev` name are never indexed, `matterofplace.com` is, and a local `bun run cf:preview` with `MOP_ENV=production` set in `.dev.vars` (B3's `scripts/dev-vars.mjs` writes `MOP_ENV=local`, which is not indexable; Verification gives the switch) answers like production on `127.0.0.1`, which is what lets the local Lighthouse and `check-seo.ts` runs see the production head; a request sent with `Host: pr-1.holy-meadow-4327.workers.dev` answers like a preview. `/admin` and `/api` are `noindex` and disallowed on production.
6. Copy rules apply to meta descriptions: calm, factual, no em dash, no hyperbole, no price, 70 to 155 characters, cut at a word boundary, written from data by pure functions (no model, S20).
7. AI-crawler policy (S44, CEO decided 2026-09-30): allow everything. No AI-specific `Disallow` rules; every crawler gets the same rules as Googlebot. `llms.txt` and `llms-full.txt` stay. Photography rights remain governed by the submission licence, not by robots.
8. `llms.txt` and `llms-full.txt` never overstate: with zero published properties they say so in one sentence.
9. Analytics load only after consent (GP-02, architecture 10). The only analytics script is gtag.js, loaded directly from `googletagmanager.com` by `loadGa4` (G31); no Tag Manager container is loaded in v1. It is injected by `Ga4Loader` only when the stored consent says `analytics: true` for the current consent `version`, never in the server-rendered HTML and never before consent on any route. The consent state is one client-side record, `{ version, analytics, decided_at }` under the key `mop_consent`, written by B3b's notice and read through `src/lib/consent.ts`; raising `CONSENT_VERSION` asks again. A browser that sends Global Privacy Control (`navigator.globalPrivacyControl === true`) is treated as declined without asking (CCPA "Do Not Sell or Share"). First-party `track()` events are anonymous and exempt, so they keep working without consent; only gtag.js waits. ASSUMED: consent is required everywhere rather than only where law demands, because region detection is more code than the rule costs.
10. Taken-down pages answer `410 Gone` (GP-03). A slug whose property has `taken_down_at` set returns status 410 from the page route and from `GET /api/public/properties/:slug`, with a short calm page ("This property is no longer listed"), `noindex`, and the same HTML shell as other pages; it is absent from the sitemap, `llms.txt` and archive counts. A slug that never existed, or a property that is only unpublished or draft, stays 404 (cached 60 seconds). The state is decided from the catalog snapshot (the set of taken-down slugs), never by a per-request table query. The 410 page is identical for every visitor and cached like any public page under the rule 3 key; the takedown bumps `catalog_version`, so the old 200 is never served after it (no purge needed). The slug is never reused.
11. Redirected slugs never appear in the sitemap or in `llms` files (GD-02): any path that is an active `redirects.from_path` or an old slug in `slug_history` is excluded, and every URL in the sitemap answers 200 without a redirect. The canonical of a page reached through an old slug is the current slug.
12. Structured data and `llms.txt` are validated in CI, not only by the owner (GQ-02). JSON-LD builders are typed with `schema-dts` so `bun run check` fails on a field Schema.org does not define; a parser test runs per page type; `scripts/validate-llms.ts` checks the `llms` files. The budget is enforced per PR (GQ-01): the PR fails on the hard limits (LCP 2.5 s, CLS 0.1, JavaScript 150 KB), and the tighter targets below are warnings.
13. Caching contract (architecture 13). Every public read in this slice goes through `getPublicState` and `getCatalog` (rule 1): sitemap, `llms` files, archive pages, gone state, the coming-soon and `noindex` decisions (`coming_soon_global` and `coming_soon_markets`), `archive_pages` and the redirect exclusions (`redirects` and `slug_history` from the snapshot). Nothing here is personal or varies by cookie or header (rule 5): the HTML of a page is the same for every visitor, `Ga4Loader` and consent act in the browser after hydration, and `X-Robots-Tag` and the request id are added by the middleware after the cache lookup and never stored; this slice adds no inline script with a per-request nonce or any other per-request value to the HTML (an enforced CSP uses hashes: B17 computes the policy, and B3 stores the policy header with that page's cache entry, so a hit and a miss answer with the same policy, F25 d; the other security headers are added by B1b's middleware after the lookup). `robots.txt` is a pure function of the host and reads nothing from the database; only the indexable body is stored: when `isIndexableHost(host, env)` holds the route calls `cachedResponse(request, "doc", () => buildRobots(host, env))`, otherwise it never calls the cache module and returns `buildRobots(host, env)` directly with `x-mop-cache: bypass`, so neither the memory layer nor the Cache API can hand one host's body to another. Documents are `GET`/`HEAD` only; none is on the never-cached list (rule 6), and no write path exists in this slice. No outside API is called on a page view (rule 10: the IndexNow ping lives in the `purge_cache` step, never in a request). Query strings are dropped from the key (rule 3), so `/sitemap.xml?x=1` hits the same entry.
Events emitted: none. New analytics event added to `AnalyticsEvent`: `archive_view` (tracked on archive pages). `consent_set` exists from B3b, whose notice tracks every click; `Ga4Loader` tracks it only for an automatic change, `track("consent_set", { analytics: false, via: "gpc" })` once per browser session (flag `mop_consent_gpc_tracked` in `sessionStorage`) when `navigator.globalPrivacyControl === true` overrides a stored grant, and never from an `onConsentChange` caused by the notice, so a click is counted once. Both are first-party and anonymous; every user action calls `track()`.
Permissions: public reads. The check script needs no credentials.

- Cache kind: architecture 13 rule 3 names three key kinds, `html`, `json` and `doc` (F25 c). Sitemap, `llms` files and robots are `doc`; archive pages and the 410 page are `html`; the API 410 answer is `json`.
- Snapshot completeness (UNPROVEN until B2 and B3 land, except that the snapshot carries the enabled `redirects` and `slug_history`, F25 b): the in-memory sitemap, `llms`, archive and gone logic needs `public_catalog_snapshot()` to also carry `architect`, `style`, `city`, `state`, `updated_at`, media variants, `og_image_key`, `video` and the key `gone`. If B2 leaves any out, the field is added to the RPC there, not fetched by a second query here.
- Cache correctness for takedown: a takedown bumps `catalog_version`, so the 410 is visible within 15 seconds without a purge; step 11's live curl waits for that window or runs with `CATALOG_VERSION_TTL_MS=0`.
- GQ-02: `schema-dts` checks field names and shapes at compile time only; it does not prove Google accepts the page, which stays an owner check. The per-type parser tests and `validate-llms.ts` catch regressions, not new Schema.org rules.
