## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs
- Published rows only (`properties.editorial_state = 'published'`, `stories.editorial_state = 'published'`, markets, regions), `markets.coming_soon`, `settings.coming_soon_global`, `property_media.variants`, approved `cover` and `reel` assets, `siteConfig`.

- `properties.taken_down_at` (B7: set on a rights or owner takedown), `slug_history` and active `redirects` rows (B2, edited in B7 screen 24), the stored consent state (B3b banner, read client side only).
Outputs
- `pageHead()` extended (below), route `head()` on every route, `src/lib/jsonld.ts` builders, routes `robots.txt`, `sitemap.xml`, `llms.txt`, `llms-full.txt`, archive route `/archive/$kind/$slug`.
- Cache: catalog-derived documents are cached at the edge with `Cache-Tag: catalog` and purged by the existing `purge_cache` step on publish and unpublish.
Invariants
1. One brand per title: routes pass bare titles; `pageHead` adds the suffix once (G-003, already fixed and enforced by `tests/unit/seo.test.ts`; this slice keeps that test green and adds cases).
2. One canonical per URL: absolute, `https`, apex host `matterofplace.com`, no query string, no fragment, no trailing slash except `/`. Filters and utm parameters never enter the canonical. `www` redirects to apex at Cloudflare (L1).
3. Thin pages stay out of the index. A market, region or `/properties` page with zero published properties is `noindex, follow` and absent from the sitemap while empty (ASSUMED, this follows S30: the coming-soon state is for visitors, not for search). The flag flips automatically when the first property is published because the head is computed from data. Archive pages exist only when their count is 3 or more and the `archive_pages` flag (B3b) is not switched off; below the threshold, or with the flag off, the URL returns 404 (`notFound()`), not a soft page, and the sitemap, `llms` files and `ArchiveLink` treat every facet as absent.
4. No invented facts anywhere in structured data: an absent field is omitted, never defaulted. No street address or coordinates for a property unless the row has a public address (ASSUMED: city level only, `geo` omitted, because owners are high-net-worth and exact location is the agent's to share). `offers` only when status is `Active`. Contact points only when `siteConfig.contact` has values. Nothing about price being merit.
5. Preview and non-production hosts are never indexed: any host other than `matterofplace.com` (preview `pr-<n>.holy-meadow-4327.workers.dev` and the production Worker on `matter-of-place.holy-meadow-4327.workers.dev` until L1 attaches the domain, E2) gets `X-Robots-Tag: noindex, nofollow` on every response and a `Disallow: /` robots body. `/admin` and `/api` are `noindex` and disallowed on production.
6. Copy rules apply to meta descriptions: calm, factual, no em dash, no hyperbole, no price, 70 to 155 characters, cut at a word boundary, written from data by pure functions (no model, S20).
7. AI-crawler policy (S44, CEO decided 2026-09-30): allow everything. No AI-specific `Disallow` rules; every crawler gets the same rules as Googlebot. `llms.txt` and `llms-full.txt` stay. Photography rights remain governed by the submission licence, not by robots.
8. `llms.txt` and `llms-full.txt` never overstate: with zero published properties they say so in one sentence.
9. Analytics load only after consent (GP-02, architecture 10). GA4 and Tag Manager are injected by `Ga4Loader` only when the stored consent says `analytics: true` for the current consent `version`, never in the server-rendered HTML and never before consent on any route. The consent state is one client-side record, `{ version, analytics, decided_at }` under the key `mop_consent`, written by B3b's notice and read through `src/lib/consent.ts`; raising `CONSENT_VERSION` asks again. A browser that sends Global Privacy Control (`navigator.globalPrivacyControl === true`) is treated as declined without asking (CCPA "Do Not Sell or Share"). First-party `track()` events are anonymous and exempt, so they keep working without consent; only the third-party container waits. ASSUMED: consent is required everywhere rather than only where law demands, because region detection is more code than the rule costs.
10. Taken-down pages answer `410 Gone` (GP-03). A slug whose property has `taken_down_at` set returns status 410 from the page route and from `GET /api/public/properties/:slug`, with a short calm page ("This property is no longer listed"), `noindex`, and the same HTML shell as other pages; it is absent from the sitemap, `llms.txt` and archive counts. A slug that never existed, or a property that is only unpublished or draft, stays 404. The 410 response is cached under `Cache-Tag: catalog` and purged by the `property.unpublished` recipe. The slug is never reused.
11. Redirected slugs never appear in the sitemap or in `llms` files (GD-02): any path that is an active `redirects.from_path` or an old slug in `slug_history` is excluded, and every URL in the sitemap answers 200 without a redirect. The canonical of a page reached through an old slug is the current slug.
12. Structured data and `llms.txt` are validated in CI, not only by the owner (GQ-02). JSON-LD builders are typed with `schema-dts` so `bun run check` fails on a field Schema.org does not define; a parser test runs per page type; `scripts/validate-llms.ts` checks the `llms` files. The budget is enforced per PR (GQ-01): the PR fails on the hard limits (LCP 2.5 s, CLS 0.1, JavaScript 150 KB), and the tighter targets below are warnings.
Events emitted: none. New analytics events added to `AnalyticsEvent`: `archive_view` (tracked on archive pages) and `consent_set` with `analytics: boolean` (tracked by the loader when the stored choice changes; first-party, anonymous; every user action calls `track()`).
Permissions: public reads. The check script needs no credentials.

## Risks and gotchas (link GOTCHAS ids)
- G-003: title suffix logic is enforced by test; do not regress it while extending `pageHead`.
- G-005: routes read through `src/lib/queries.ts` and `services`; the new archive route and the seo builders do too, and the server-side documents (sitemap, llms, robots) import server modules only in `src/server/seo`, never from a route component.
- G-004: none of this changes `src/domain` field names; `archive_facets` is a view, not a shared shape. If a `Property.video` field is used by `videoLd`, it is B12's.
- G-007: `archive.css` tokens only. G-011: no paid feature; Lighthouse CI runs on the free runner.
- Static file shadowing: deleting `public/robots.txt` is mandatory; leaving it makes the dynamic route dead code and the preview-host protection fail silently.
- Cloudflare offers dashboard-managed robots and AI-bot blocking. If those are switched on they add or override rules; the owner checks the live `robots.txt` after switching anything (UNPROVEN until L1).
- Coming-soon versus SEO: production launches with no properties, so most pages are `noindex` by design; do not "fix" that by indexing empty pages. Search Console will show "Excluded by noindex", which is expected.
- The dev seed is illustrative (S30). The sitemap and llms documents built on dev show it; production never does. `check-seo.ts --production` fails if any URL contains `/property/` while zero rows are published.
- Structured data for a listing that is not for sale (`Off-market`, `Under offer`, `Sold`): no `offers`; wording stays editorial. Sold prices are never published.
- Image sitemap entries expose photo URLs; only variants already public on R2 are listed, never originals.
- IndexNow requires the key file to be reachable; the static `public/<key>.txt` is fine, it is not a page.
- GA4 and Tag Manager: `track()` feeds `dataLayer` and first-party `analytics_events` regardless; the container itself loads only through `Ga4Loader` after consent (invariant 9). B3b owns the notice and its copy, B16 the privacy wording that must say what GA4 collects and that declining or Global Privacy Control stops it. The measurement id is public (`VITE_GA4_MEASUREMENT_ID`, G-006) and the G-006 proof line already lists it. Consent records live in the visitor's browser only, so the plan cannot prove consent per person; it proves that nothing loads without it. UNPROVEN: a Tag Manager container configured in the dashboard with its own triggers can load tags this code knows nothing about; the owner keeps the container empty until the notice is live.
- GP-03: the 410 depends on `properties.taken_down_at` from B7 step 7a; until then step 11 runs on a fixture row. Setting the response status from a TanStack Start loader uses the Start server API, UNPROVEN until step 11 runs; the fallback is a server route in front of `property.$slug` that decides 410 before rendering. Search engines treat 410 as a stronger "gone" than 404, which is the intent; sitemap exclusion is what makes them stop asking.
- GD-02: old-slug 301s are served by B3 and B7's redirect rows, not here; this slice only keeps those paths out of the sitemap and `llms` files and checks the canonical of the target.
- GQ-01: hard limits fail the PR, tighter targets warn, so a noisy lab run does not block merges for a 0.05 s wobble; Lighthouse variance on a shared runner is real, so the `seo` job runs three times and takes the median (`numberOfRuns: 3`).
- B17 overlap: B17's items on robots, sitemap, `llms` files and structured data are tests against the output of this slice (`check-seo.ts`, the unit tests above), not new files; B17 creates no second robots, sitemap or `llms` route.
- GQ-02: `schema-dts` checks field names and shapes at compile time only; it does not prove Google accepts the page, which stays an owner check. The per-type parser tests and `validate-llms.ts` catch regressions, not new Schema.org rules.
