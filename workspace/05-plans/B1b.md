Invariants
1. Nothing under the app folder is named `.github` (G-012). Every workflow job sets `working-directory: Matter Of Place Codebase` through `defaults.run`.
2. `wrangler.toml` contains no secret and no binding for Queues, Browser Rendering, Images, Durable Objects or KV (G-011). Proof grep in Verification.
3. `MOP_ENV` defaults to `production` in the file, so a deploy that forgets its override fails safe (hides illustrative content, see B3b).
4. The Worker name in `wrangler.toml` and in `vite.config.ts` (`cloudflare.wrangler.name`) is `matter-of-place` (G-002). Previews override the name at deploy time only.
5. Free tier only. The only paid item is the domain (P-009, S21). Preview Workers are deleted when their PR closes (`wrangler delete --name pr-<n> --force`, which exits 0 with the deploy token because it holds KV read, E1) so the account stays under the free Worker count (ASSUMED limit of 100 Workers per account; re-check in HARDEN). Nothing in this slice starts Docker or the Supabase local stack (S50, P-038).
6. `deploy.yml` never runs on a fork PR (`github.event.pull_request.head.repo.full_name == github.repository`).
7. Sentry never receives personal data (GS-03). The client sends the error class, a message run through the scrub, stack frames, and the tags `request_id`, `route`, `env`, `release`. It never sends emails, names, message bodies, IP addresses, cookies, `authorization`, query strings or request bodies. One exported pure function `scrubEvent(event)` is applied last, in the role of `beforeSend`: it deletes `user`, `request.data`, `request.cookies`, `request.headers`, `request.query_string`, `contexts.geo` and all breadcrumbs, replaces email-shaped strings with `[email]`, and truncates every exception value to 200 characters (ASSUMED limit). The name is kept so the `@sentry/cloudflare` fallback maps to it one to one.
8. The toolchain is pinned (GS-07). `package.json` `engines` holds `{"bun": "1.3.13", "node": "24.x"}` (the pin follows the laptop's local major, node 24.13.0, E11), `bun.lock` is committed, CI runs `bun install --frozen-lockfile`, and a CI step fails when the setup-bun and setup-node versions differ from `engines`. Dependabot opens grouped weekly PRs for the app (`bun` ecosystem, directory `/Matter Of Place Codebase`) and for `github-actions` (directory `/`); a Dependabot PR is an ordinary PR for `ci.yml`, but GitHub withholds Actions secrets from Dependabot-triggered runs, so its `preview` job is skipped (`github.actor != 'dependabot[bot]'`); a preview for Dependabot PRs is BLOCKED until the operator decides to copy the preview secrets into Dependabot secrets (`gh secret set --app dependabot`).
9. Edge rules live in code, not in a dashboard memory (GS-08). `scripts/cf-edge.mjs` is idempotent and has three parts: the Cloudflare Free Managed Ruleset executed in phase `http_request_firewall_managed` (its ruleset id is looked up by name at run time, not hard coded), Bot Fight Mode on, and the zone's single free rate-limit rule on `starts_with(http.request.uri.path, "/api/public/")` at 60 requests per 10 seconds per IP with action block (ASSUMED threshold; the free plan allows one rule and a 10 second window, P-009). No geo block on `/admin`: agents run anywhere, so `/admin` is protected by the session or the agent key only (B7). The rules apply to the zone, so they exist only after Stage 5 routes the domain to the Worker; `workers.dev` hostnames are not covered.

Events emitted: none (`AnalyticsEvent` unchanged). Permissions: only the repo owner can push `main` and read Actions secrets; the Cloudflare deploy token in GitHub holds exactly Workers Scripts Write, Workers R2 Storage Write and Workers KV Storage Read on this account (E1; KV read is there only because `wrangler delete` lists KV namespaces). It cannot tail: `wrangler tail` runs from the owner's shell with the local `mop-admin` token. Edge rules need no new operator token (F19): `scripts/cf-edge.mjs` reads `CF_EDGE_TOKEN` and falls back to `CLOUDFLARE_API_TOKEN` from the local `.env` (the admin token `mop-admin`); it is run by hand from the owner's shell and neither token is stored in GitHub for it.

## Risks and gotchas (link GOTCHAS ids)
- G-012: workflows only work at the repo root. `defaults.run.working-directory` is set per job, and `paths-ignore` uses root-relative paths (`workspace/**`).
- G-002: `vite.config.ts` stays the single build config; this slice edits it only if step 2 proves Nitro drops `vars`. The worker name stays pinned.
- G-006: `VITE_TURNSTILE_SITE_KEY` is public by design. The G-006 proof line names three variables; update that entry to four when this lands.
- G-011 and P-009: Actions minutes. CI on a PR is about 2 minutes for `check` and 1.5 for `build`; production deploy about 4; backup about 2 per night, so roughly 60 of 2,000 minutes a month. UNPROVEN until measured on the first ten runs.
- CPU limit: free Workers allow 10 ms CPU per request. Measured 2026-10-01 on a throwaway Worker (E3): home 6 to 52 ms, `/properties` 10 to 24 ms, other routes 2 to 15 ms, no error 1102 across 36 requests, so the home page and the collection sit above the documented limit and the risk stays open. Step 7 measures again on the real Worker. If it fails, record the number and add a decision to `PROJECT-STATE.md` (edge-cache the HTML on the custom domain first, Workers Paid at 5 USD second). Do not add a paid binding silently.
- Cache API does not work on `workers.dev` hostnames. Preview shows no edge caching; cache headers are asserted, caching itself is proved after the custom domain exists (Stage 5).
- Branch protection is unavailable on this private repository (observed 403 above); Environments are unavailable on the same plan (E9). Step 9 ends as BLOCKED with the reason recorded if the plan does not allow it.
- Direct Supabase connections are IPv6 only on the free plan and GitHub runners have no IPv6, so `backup.yml` must use the pooler string. Dump through the pooler works from the laptop (E4: client 18.4, server 17.11, exit 0, 70 table entries); the runner path stays UNPROVEN until step 8's restore listing succeeds; a full restore rehearsal is HARDEN (architecture 7).
- `wrangler secret bulk` needs the Worker to exist, so preview deploys first and sets secrets second; a first request in that gap sees missing secrets and returns the calm 500. Acceptable for previews.
- CSP ships as Report-Only. TanStack Start injects inline scripts, so an enforcing policy needs nonces or hashes; that is HARDEN. Fonts load from Google (`fonts.googleapis.com`, `fonts.gstatic.com`) until B17 self-hosts them (G-014), so both are in the table now and B17 removes the rows.

Add `wrangler` and `sharp`/`supabase` to `trustedDependencies` in B2 if their postinstall is needed; here only `wrangler` (no postinstall required, verify in step 2). - GS-03: exception messages can carry user input (a validation error that echoes an email). `scrubEvent` masks email-shaped strings and truncates to 200 characters, but a name in free text cannot be detected; the rule for server code is to throw messages that name the field, never the value.
