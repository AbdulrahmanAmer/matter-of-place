Edge rules live in code, not in a dashboard memory (GS-08). `scripts/cf-edge.mjs` is idempotent and B1b writes six of its parts: (1) the Cloudflare Free Managed Ruleset executed in phase `http_request_firewall_managed` (its ruleset id is looked up by name at run time, not hard coded), (2) Bot Fight Mode on, (3) the zone's single free rate-limit rule on `starts_with(http.request.uri.path, "/api/public/")` at 60 requests per 10 seconds per IP with action block (ASSUMED threshold; the free plan allows one rule and a 10 second window, P-009), and the three zone settings of G32: (6) the `www` to apex 301 redirect, (7) Always Use HTTPS on, (8) SSL mode Full (strict). No geo block on `/admin`: agents run anywhere, so `/admin` is protected by the session or the agent key only (B7), the session verified locally against the project's ES256 key (E14) with no call to Supabase Auth. The rules apply to the zone, so they exist only after Stage 5 routes the domain to the Worker; `workers.dev` hostnames are not covered.

10. Pipeline order and never-cached list (architecture 13 rules 5 and 6). Order, outside to inside: (a) mint or accept `x-request-id` (an inbound value is kept only when it matches `^[A-Za-z0-9-]{8,64}$`, otherwise `crypto.randomUUID()` is minted, so a client cannot put arbitrary text into logs, error bodies, Sentry tags or `audit_log`), (b) never-cached rule, (c) the cache hook, (d) render. Headers from (a) and the static security headers are added to the response after (c) returns and are never passed to the cache store, so a cached render is identical for every visitor. The one exception is the Content-Security-Policy header: B17 computes the script hashes of a page's inline scripts at render and B3 stores that header with the page's cache entry (F25 d), so a hit and a miss answer with the same policy. After (c) returns, the pipeline sets the default policy from `cspFor(env, flags)` only when the response carries neither `Content-Security-Policy` nor `Content-Security-Policy-Report-Only`; it never overwrites one that came from the render or the stored entry. `Cache-Control: no-store` is forced by (b) on every POST, every write under `/api/public/`, all of `/api/admin/*`, `/api/hooks/*` and `/admin`, preview-token pages (a URL carrying a `preview` or `draft_token` search parameter; such a request also skips the cache hook; B7 issues the tokens, the detection for the pipeline lives here), any response carrying `Set-Cookie`, and every 5xx (including the calm 500). Public HTML answers `Cache-Control: public, max-age=0, must-revalidate` to the browser; the edge lifetime (`s-maxage=300, stale-while-revalidate=86400`) belongs to the stored copy inside B3's module. Until B3 lands the cache hook is a pass-through. B1b adds no database call and no table read: it has no public read of its own, and the only server route it adds (`sentry-test`) never touches the database. Any later public read goes through `getPublicState` and `getCatalog` (B3), which take an injectable database client, never a table. `public_state()` returns `catalog_version`, flags, `coming_soon_global`, `coming_soon_markets`, `site` and `illustrative_content`, and the snapshot carries `redirects` and `slug_history`; these key names are final (F25 b). Writes to the public `settings` keys (`flags`, `coming_soon_global`, `site`, `environment`, `og_static`; channel and token keys do not bump, G21), `markets.coming_soon`, `redirects` and `slug_history` bump `catalog_version` through B2's triggers, so the `flags` that `securityHeaders` and `cspFor` receive come from `deps.getFlags` (in this slice `async () => ({})`, every key off; B3b replaces it with `getFlags(db)` from `src/server/lib/flags.ts`, which reads B3's `getPublicState`) and a flag change reaches cached pages within 15 seconds with no code bumping the version by hand. H1 counts real queries with `pg_stat_statements` (E15), and B4's counting client proves zero queries on a warm read. Later slices insert into `handle` at fixed places and nowhere else: (b2) B17's `maintenanceGate(request, flags, env)` between (b) and (c), so a cached page never masks the switch; (d) becomes `withPageCsp(render, env, flags)` from B17's `headers.ts`, which wraps `deps.render`; (c2) B14's `deps.notFound?.(request, ctx)` right after (c) returns, for a GET answered 404 from a hit or a render. Each of those slices adds its own case to `pipeline.test.ts`; no slice changes the order of (a) to (d).
11. Release id. `SENTRY_RELEASE` is the git commit of the build and is passed as `--var SENTRY_RELEASE:<sha>` by both deploy jobs, so B3's cache key (`https://cache.mop.internal/<release>/v<catalogVersion>/<kind>/<pathname>`, kind `html`, `json` or `doc`) changes on every deploy and HTML never points at the asset files of a previous build. A local run without it falls back to `dev`.
12. The enforced Content-Security-Policy uses hashes, never a per-request nonce, because HTML is cached (architecture 13 rule 5). `cspFor` has a slot for script hashes from the first slice; B17 computes the hashes of a page's inline scripts at render, B3 stores the resulting header with that page's cache entry, and H1 flips the policy to enforcing.
