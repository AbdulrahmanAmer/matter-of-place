2. `wrangler.toml` contains no secret and no binding for Queues, Browser Rendering, Images, Durable Objects or KV (G-011). Proof grep in Verification.
3. `MOP_ENV` defaults to `production` in the file, so a deploy that forgets its override fails safe (hides illustrative content, see B3b).
4. The Worker name in `wrangler.toml` and in `vite.config.ts` (`cloudflare.wrangler.name`) is `matter-of-place` (G-002). Previews override the name at deploy time only.
5. Free tier only. The only paid item is the domain (P-009, S21). Preview Workers are deleted when their PR closes (`wrangler delete --name pr-<n> --force`, which exits 0 with the deploy token because it holds KV read, E1) so the account stays under the free Worker count (ASSUMED limit of 100 Workers per account; re-check in HARDEN). Nothing in this slice starts Docker or the Supabase local stack (S50, P-038).
6. `deploy.yml` never runs on a fork PR (`github.event.pull_request.head.repo.full_name == github.repository`).
7. Sentry never receives personal data (GS-03). The client sends the error class, a message run through the scrub, stack frames, and the tags `request_id`, `route`, `env`, `release`. It never sends emails, names, message bodies, IP addresses, cookies, `authorization`, query strings or request bodies. One exported pure function `scrubEvent(event)` is applied last, in the role of `beforeSend`: it deletes `user`, `request.data`, `request.cookies`, `request.headers`, `request.query_string`, `contexts.geo` and all breadcrumbs, replaces email-shaped strings with `[email]`, and truncates every exception value to 200 characters (ASSUMED limit). The name is kept so the `@sentry/cloudflare` fallback maps to it one to one.
8. The toolchain is pinned (GS-07). `package.json` `engines` holds `{"bun": "1.3.13", "node": "24.x"}` (the pin follows the laptop's local major, node 24.13.0, E11), `bun.lock` is committed, CI runs `bun install --frozen-lockfile`, and a CI step fails when the setup-bun and setup-node versions differ from `engines`. Dependabot opens grouped weekly PRs for the app (`bun` ecosystem, directory `/Matter Of Place Codebase`) and for `github-actions` (directory `/`); a Dependabot PR is an ordinary PR for `ci.yml`, but GitHub withholds Actions secrets from Dependabot-triggered runs, so its `preview` job is skipped (`github.actor != 'dependabot[bot]'`); a preview for Dependabot PRs is BLOCKED until the operator decides to copy the preview secrets into Dependabot secrets (`gh secret set --app dependabot`).
9. Edge rules live in code, not in a dashboard memory (GS-08). `scripts/cf-edge.mjs` is idempotent and has three parts: the Cloudflare Free Managed Ruleset executed in phase `http_request_firewall_managed` (its ruleset id is looked up by name at run time, not hard coded), Bot Fight Mode on, and the zone's single free rate-limit rule on `starts_with(http.request.uri.path, "/api/public/")` at 60 requests per 10 seconds per IP with action block (ASSUMED threshold; the free plan allows one rule and a 10 second window, P-009). No geo block on `/admin`: agents run anywhere, so `/admin` is protected by the session or the agent key only (B7), the session verified locally against the project's ES256 key (E14) with no call to Supabase Auth. The rules apply to the zone, so they exist only after Stage 5 routes the domain to the Worker; `workers.dev` hostnames are not covered.

10. Pipeline order and never-cached list (architecture 13 rules 5 and 6). Order, outside to inside: (a) mint or accept `x-request-id`, (b) never-cached rule, (c) the cache hook, (d) render. Headers from (a) and the static security headers are added to the response after (c) returns and are never passed to the cache store, so a cached render is identical for every visitor. The one exception is the Content-Security-Policy header: B17 computes the script hashes of a page's inline scripts at render and B3 stores that header with the page's cache entry (F25 d), so a hit and a miss answer with the same policy. After (c) returns, the pipeline sets the default policy from `cspFor(env, flags)` only when the response carries neither `Content-Security-Policy` nor `Content-Security-Policy-Report-Only`; it never overwrites one that came from the render or the stored entry. `Cache-Control: no-store` is forced by (b) on every POST, every write under `/api/public/`, all of `/api/admin/*`, `/api/hooks/*` and `/admin`, preview-token pages, any response carrying `Set-Cookie`, and every 5xx (including the calm 500). Public HTML answers `Cache-Control: public, max-age=0, must-revalidate` to the browser; the edge lifetime (`s-maxage=300, stale-while-revalidate=86400`) belongs to the stored copy inside B3's module. Until B3 lands the cache hook is a pass-through. B1b adds no database call and no table read: it has no public read of its own, and the only server route it adds (`sentry-test`) never touches the database. Any later public read goes through `getPublicState` and `getCatalog` (B3), which take an injectable database client, never a table. `public_state()` returns `catalog_version`, flags, `coming_soon_global`, `coming_soon_markets`, `site` and `illustrative_content`, and the snapshot carries `redirects` and `slug_history`; these key names are final (F25 b). Writes to flags, `coming_soon_global`, settings, `markets.coming_soon`, redirects and slug history bump `catalog_version` by B2's triggers, so the `flags` that `securityHeaders` and `cspFor` receive come from B3's `getFlags` and a flag change reaches cached pages within 15 seconds with no code bumping the version by hand. H1 counts real queries with `pg_stat_statements` (E15), and B4's counting client proves zero queries on a warm read.
11. Release id. `SENTRY_RELEASE` is the git commit of the build and is passed as `--var SENTRY_RELEASE:<sha>` by both deploy jobs, so B3's cache key (`https://cache.mop.internal/<release>/v<catalogVersion>/<kind>/<pathname>`, kind `html`, `json` or `doc`) changes on every deploy and HTML never points at the asset files of a previous build. A local run without it falls back to `dev`.
12. The enforced Content-Security-Policy uses hashes, never a per-request nonce, because HTML is cached (architecture 13 rule 5). `cspFor` has a slot for script hashes from the first slice; B17 computes the hashes of a page's inline scripts at render, B3 stores the resulting header with that page's cache entry, and H1 flips the policy to enforcing.

Events emitted: none (`AnalyticsEvent` unchanged). Permissions: only the repo owner can push `main` and read Actions secrets; the Cloudflare deploy token in GitHub holds exactly Workers Scripts Write, Workers R2 Storage Write and Workers KV Storage Read on this account (E1; KV read is there only because `wrangler delete` lists KV namespaces). It cannot tail: `wrangler tail` runs from the owner's shell with the local `mop-admin` token. Edge rules need no new operator token (F19): `scripts/cf-edge.mjs` reads `CF_EDGE_TOKEN` and falls back to `CLOUDFLARE_API_TOKEN` from the local `.env` (the admin token `mop-admin`); it is run by hand from the owner's shell and neither token is stored in GitHub for it.
