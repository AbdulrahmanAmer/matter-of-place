# B9 — Creative system

Lane: Turn listings into content · Stage: 3 BUILD (carries the Stage 1 creative-direction gate, completion map Stage 3 note in PROJECT-STATE log) · Owner agent: mop-designer for steps 1 and 2 (direction), then mop-builder · Depends on: B8 (jobs, `render.yml`, callback, step registry), B2 (R2 layout, `property_media.variants`, `db:push`, `gen:types`), B4 (Vitest projects, the `db` project and `tests/db` harness, Playwright config), B12 (the `findChrome()` `CHROME_PATH` change in `launch/engine/chrome.mjs`; this slice keeps a fallback and does not wait for it), B7 steps 1 to 3 (actor, authz, audit, `src/admin/ui`) for step 10 and 11 · Unblocks: B10 (posts what B9 approves), B11 (newsletter block, standalone email), B12 (reel is an `assets` kind), B13 (OG image), B14 (audit reads asset backlog)

## Goal and observed exit
Every published property produces its owned creative without a designer in the loop: cover 1200×630 (with an X crop 1200×675 and a LinkedIn crop 1200×627 rendered beside it), carousel 1080×1350 with 6 to 8 slides (plus a 1080×1080 LinkedIn set of its first 3 to 4 images), story 1080×1920, newsletter block, and (Campaign tier only, S24) standalone email; captions and alt text written by Haiku (S20) under brand-voice lint, in three variants per property (Instagram, X short, LinkedIn editorial, S48); everything lands in `assets` as `pending` and waits for a human on `/admin › Assets` (screen 10, S23).
Observed exit (completion map B9): "PNGs for one property match the chosen design." Proof is three things together: the CEO's picks recorded in `workspace/08-creative/DIRECTION.md` and PROJECT-STATE; a render run of the fixture property whose PNG dimensions are asserted by a script; a contact sheet of the run placed next to the chosen option PNGs for a human match check.

## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs
- Event `property.published` (architecture 3.6) fans out to the steps `render_cover`, `render_carousel`, `render_story`, `write_captions`, `build_newsletter_block` (and `render_variants`, owned by B2; `render_reel` owned by B12). Payload carries `{ property_id, slug, tier, market }`; ASSUMED the fan-out payload is that fixed shape (B8b to confirm).
- Step module shape from B8: `{ type, heavy, paramsSchema, run(ctx, params, payload), onResult? }`.
- A render spec, built deterministically from the property row and its `property_media.variants` (thumb, card, hero, og, carousel): `RenderSpec = { kind, property: { id, slug, title, city, state, market, price, currency, beds, baths, interiorSqFt, yearBuilt, type }, images: [{ url, alt, orientation, w, h }], slides?: SlideSpec[], out: { r2_prefix } }`. Payload stays under the 64 KB dispatch limit (B8) because it carries URLs and text only.
- Haiku through the Anthropic API for `write_captions` only. Secret `ANTHROPIC_API_KEY` in Supabase function secrets, never `VITE_*` (G-006); no Anthropic account or key exists yet (E9), so it is set with `supabase secrets set` once the operator supplies it, and everything that calls the live model is BLOCKED until then (tests use a mocked client). Model id stored in `settings.caption_model`; ASSUMED default a current Haiku id, confirm at build.

Outputs
- `assets` rows, one per `(property_id, kind, revision)`: `files` (`[{ r2_key, w, h, bytes, role }]`, `role` is an ASSUMED extra key used by B12 for `video` and `poster`, and by this slice for the channel crops: `x` (1200×675) and `linkedin` (1200×627) on the `cover` asset, `linkedin_set` (1080×1080, 3 to 4 files) on the `carousel` asset; no new asset kind), `caption` (the Instagram caption), `alt_text`, `meta jsonb` (ASSUMED new column: `captions { instagram, x, linkedin }` (the `caption` column mirrors `captions.instagram`), `slide_alts[]`, `spec_hash`, `caption_lint`, newsletter block copy, standalone subject and preheader), `status`.
- Files in R2 at `assets/<property_id>/<kind>/r<revision>/<name>.png`, immutable, public through the R2 custom domain (ASSUMED `media.matterofplace.com`, B2 owns; Meta must be able to fetch it, see B10). R2 is off and no bucket exists (E8, S50): every upload and every public URL is BLOCKED until the operator turns R2 on, so the render scripts have a local mode (`--out <dir>`, no upload) that every step before step 10 uses.
- Static OG set for non-property pages (home, markets index, each market, stories index, default) at `og/static/<key>.png`, rendered by `scripts/render-og-static.mjs` (consumed by B13).
- Events: `asset.approved` and `asset.rejected` (both already in the 14 catalog types) emitted by the approve and reject server functions. No new event types.

Invariants
1. Nothing here posts, sends or publishes. Output only ever reaches `pending` (S23). Approval is a separate human action (or the auto path defined in B10).
2. Determinism: same `spec_hash` means same pixels. Templates take data only; no clocks, no randomness, no network inside a template. Fonts are self-hosted files, never a CDN.
3. Idempotency: recipe jobs use `event_id:step_id` (B8). A re-render is a new `revision` row plus a manual job key `render_<kind>:<property_id>:<revision>`; the old revision becomes `rejected` with note `superseded`.
4. An asset cannot become `approved` unless `files` is non-empty, `caption` is non-empty and `alt_text` is non-empty (trigger `assets_approve_guard`). A reject needs a note.
5. Brand voice is checked by code, not trusted to the model: no em dashes, no words from the banned list (stunning, dream, must-see, luxury living, "just listed" and the rest in `src/server/assets/voice.ts`), no exclamation marks, at most 2,200 characters for Instagram, 280 for the X caption with the property link counted at its shortened length (ASSUMED 23, UNPROVEN, confirmed by B10 step 3a) and 3,000 for LinkedIn (ASSUMED, UNPROVEN), no hashtags at launch (ASSUMED), no guarantee language (leads, buyers, sales), no price framed as merit, every number in a caption must appear in the property row. A caption that fails lint twice is stored with `meta.caption_lint = "failed"` and cannot be approved until a human edits it.
6. The visual grammar is fixed by the chosen direction: small wordmark, dominant image, LOCATION, price, minimal specs ("5 BED · 4.5 BATH · 4,320 SF"). No gradient, glow, gold, big agent headshot, or "JUST LISTED" (mop-designer brand rules, G-007).
7. Tier gate: `standalone_email` and `reel` assets are created only when `payload.tier = "Campaign"` (S24). The step re-checks the tier itself, so a mis-edited recipe cannot spend Actions minutes.

Permissions (admin-screens 10, architecture 3.7)
| Action | Roles |
|---|---|
| list, get assets | all six roles |
| approve, reject, re-render | media_ops, chief_editor. Agents: same routes by bearer key, scope `assets`; an agent approval is honoured only in `auto` mode after `auto_after` (B10 guard) |
| edit caption and alt | media_ops, chief_editor |
| render hook | no session, HMAC only (B8) |

## Risks and gotchas (link GOTCHAS ids)
- G-012: the render workflow is at the repository root, `working-directory: Matter Of Place Codebase` per job.
- G-007: templates use tokens only; the social token block is added to `tokens.css` first.
- G-004: `src/domain/assets.ts` names equal generated types and snake_case columns; `meta`, `revision`, `role` change all three together.
- G-006: `ANTHROPIC_API_KEY`, R2 keys, callback secret are never `VITE_*`.
- G-011 and P-009: caption calls are the only model spend; a publish makes one Haiku call. No Browser Rendering binding: screenshots run in Actions.
- P-026-style traps: Windows path of Chrome in `launch/engine/chrome.mjs` does not exist on Linux, which is why the render scripts take `CHROME_PATH`. Verify on the runner, UNPROVEN until step 10 (BLOCKED on R2 and the dispatch token).
- P-038 and S50: no Docker, no `supabase start` or `db reset`; database proofs run on `mop-dev` through B4's `tests/db` harness. R2 is off (E8): nothing in steps 1 to 9 may need a bucket.
- Fonts: if the font file is missing the screenshot silently falls back to a system serif and the design drifts. `shoot.mjs` waits on `document.fonts.check` for both families and throws when it fails.
- Instagram carousel alt text per slide: whether the Graph API accepts `alt_text` per carousel child is UNPROVEN, checked in B10 step 3. `meta.slide_alts` is stored regardless.
- The CEO pick can take days. Steps 3 onward do not start until `DIRECTION.md` has five rows (step 1 and the preparation for step 2 can run at once); do not guess a direction to save time.
- Illustrative dev seed images may be smaller than the carousel variant; specs fall back to `hero` and the planner refuses images narrower than 1080 px with a clear job error.
