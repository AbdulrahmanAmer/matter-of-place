## Goal and observed exit
A side chat opens from a button in the admin's top bar on every screen. The operator writes a command; Second, running
on this laptop through the Claude CLI, answers within a minute and does it: runs the AI team (hire, wake, pause,
message), works the admin through its API (requests, properties, recipes, emails, newsletter, channels, jobs), changes
the website through the repository's own path (branch, check, pull request, merge gate), and makes media with the
installed skills (Qwen voiceover, the video pipeline). It has no session to lose: every run starts from a generated
atlas of everything (screens, actions, API routes, jobs, recipes, step catalog, scripts, skills) plus its own durable
notes and the recent conversation.
Observed exit: the operator writes "Second, hire a video editor and make a 20 second reel of the brand with a voiceover"
in the side chat; a Video editor appears in the office, a reel file appears in Assets with its voiceover, and Second's
reply names both.

## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs: a person's message in thread `second` (side chat), or a mention `@second` in the team chat.
Outputs: its reply in the thread; changes through the admin API, the repository's merge gate, or the installed tools.
Invariants:
1. The operator's own command is authority to act: Second does it and reports. What Second starts on its own (no
   command) goes through Approvals like any employee's proposal (W1 invariant 3).
2. Person-only actions stay person-only (team, settings, passwords; matrix `humanOnly`). Second prepares them and
   tells the operator the one click left; it never holds a session cookie or a password.
3. It reaches the admin only through the admin API with its own agent key (role admin, every scope), so every act is
   in `audit_log` under its name.
4. It changes code only through the repository's path: a branch, `bun run check`, a pull request, the merge gate.
5. Its tool policy denies reading `creds/`, `cloudflare tokens and secrets.txt`, `Claude Session.txt`, printing
   `.env` values, Docker, force pushes and history rewrites (the operator's standing rules).
6. No session: each run gets the atlas (regenerated from code when it changed), `second/notes.md` (its durable notes,
   which it may append to) and the last 40 lines of its thread.
Events emitted: none new; audit rows come from the admin API it calls.
Permissions: the side chat posts through `workforce.post_message` into thread `second`.

## Files (create / change; one line each: path — what it contains)
- app/scripts/second/atlas.mjs — writes `second/atlas.md` from nav.ts, the permission matrix, the route tree, the step
  catalog, job types, package scripts, `.claude/skills` and `~/.claude/skills` names.
- app/scripts/second/run.ts — one run: builds the prompt (atlas, notes, thread), spawns `claude -p` (Opus 5.5) in the
  repository with the tool policy, posts the reply, records the run.
- app/scripts/second/settings.json — the tool policy (allow and deny lists) passed with `--settings`.
- app/scripts/workforce/daemon.ts — claims runs of `second` first and hands them to `run.ts`.
- app/supabase/migrations/<ts>_second.sql — seeds the `second` agent row (model opus).
- app/src/admin/workforce/SideChat.tsx — the drawer: the thread, the composer, the run state; opened from the top bar.
- app/src/admin/ui/TopBar.tsx — the "Second" button.
- app/scripts/second/key.mjs — creates Second's agent key once (admin, every scope) and stores it in the laptop's
  `.env` as SECOND_AGENT_KEY (name only ever printed).
