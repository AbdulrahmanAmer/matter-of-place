The route sweep (the core of B4)
- Every page route is loaded at 1440x900 (project `desktop`) and 390x844 (project `phone`, `isMobile`, `hasTouch`) and must satisfy: HTTP 200 (or the expected status for redirects and the 404 route); exactly one `h1` (the 404 page has one: "This place is not on our map."); a `<main>` landmark; `<html lang="en">`; a `<title>` that contains "Matter of Place" exactly once (G-003); a non-empty meta description and a canonical link; no `console.error`, no uncaught page error, no failed same-origin request with status 400 or higher; every `<img>` has an `alt` attribute; no horizontal overflow (`document.documentElement.scrollWidth <= window.innerWidth`, and no element wider than the viewport outside an `overflow-x: auto` ancestor); axe with tags `wcag2a`, `wcag2aa`, `wcag21a`, `wcag21aa` reports no violation of impact `serious` or `critical` that is not in the baseline.
- Route list (`tests/e2e/fixtures/routes.ts`): static `/`, `/properties`, `/markets`, `/stories`, `/editorial-standard`, `/submit`, `/exposure`, `/about`, `/contact`, `/faq`, `/legal`; dynamic `/$market` (3), `/$market/guide` (3), `/$market/$region` (12), `/property/$slug` (16 in the full seed), `/stories/$slug` (all bundled stories); `/sitemap.xml` (status and XML content type only); not found `/no-such-page`. Redirect routes are covered by `redirects.spec.ts`, which iterates the `redirects` list of `routes.ts` and holds no case of its own: `/markets/california` to `/california`, `/place-notes` to `/stories`, `/pricing` to `/exposure`, `/california/san-diego` to `/california/la-jolla`, all 301 (four when B4 lands, three once B5 moves `/place-notes`). `/place-notes` is a redirect only until B5 step 7 replaces `src/routes/place-notes.tsx` with the Place Notes page (F8, the subscriber confirm landing page); from then it is a static route that answers 200, and the same change moves `/place-notes` from `redirects` to `staticRoutes`. `routes-covered.test.ts` makes that move mechanical: it reads each route file and requires a file whose `beforeLoad` throws `redirect(` to be mapped `redirect`, and any other page file to be mapped to a pattern, so the B5 change is red until the map follows it. The map classifies by path first (`classifyRouteFile(path)` in `routes.ts`): every file under `src/routes/api/**` is `server`, and `src/routes/admin.tsx` and every file under `src/routes/admin/**` are `admin` (covered by B7's `admin` Playwright project and its own auth setup, never by `sweep.spec.ts`); only files outside those two folders need an explicit pattern, `redirect`, `server` or `layout` entry. So a slice that adds an API or admin route file (B6 to B12, B14, B15) touches nothing here, and a slice that adds a public page or a root server file (B5 `place-notes.tsx`, B13, B16, B17) lists `tests/e2e/fixtures/routes.ts` under Change.
- The mode comes from `E2E_MODE=local|live` (default `local`), read once in `playwright.config.ts` and by `routes.ts`. In local mode the parameters come from `src/data/*`; in live mode from `GET /api/public/*` of the target, and `getDynamicRoutes("live")` first loads `/` and fails with a message naming `E2E_MODE` unless `document.body.dataset.services` is `"live"` (B3's `<body data-services>`), so a local-mode build can never be swept as if it were live. The CI `e2e` job sets `local`, `e2e-live` sets `live`. In a coming-soon database there are no property pages, so the fixture returns none and `coming-soon.spec.ts` (B3b) covers the empty states.
- The axe baseline (`tests/e2e/axe-baseline.json`) lists `{ route, rule, target, reason, ticket }`. The test fails on any violation not in the baseline (a new problem) and on any baseline entry that no longer occurs (a fixed problem must leave the list), so the file can only shrink. ASSUMED: the first run will not be clean (warm grey text tokens are a known contrast risk); every baseline entry becomes a visual-pass ticket (S40).
- Structured data and machine-readable files (GQ-02). On every page route the sweep also collects each `<script type="application/ld+json">`, parses it (a parse error fails the route), requires `@context` to be `https://schema.org`, and compares the `@type` values found (including inside an `@graph`) with `jsonLdExpectations[routeClass]` from `tests/e2e/fixtures/routes.ts`. The map starts with the types that `src/lib/seo.ts` already emits (an empty list means "any valid block is fine") and B13 fills it with the required types per route class when its builders land (home: `Organization`, `WebSite`; property: `RealEstateListing`, `BreadcrumbList`; story: `Article`; FAQ: `FAQPage`). `/robots.txt`, `/llms.txt` and `/llms-full.txt` join the route list as `seoFileRoutes` only when their route file exists under `src/routes` (the list is computed from the same directory read as `routeFileCoverage`, so it is deterministic and never an environment switch); each must answer 200 with `text/plain`, and the two `llms` files must start with an H1 line and contain only absolute `https` links. The typed builders (`schema-dts`) and the per-page-type parser tests are B13's; this is the end-to-end net under them.

Invariants
1. A new test is not finished until it has been watched failing for the right reason (global rule 2). `scripts/watchfail.mjs` does this deterministically and appends to `tests/WATCHED-FAIL.md`.
2. A patch that does not apply is a failed run, not a green one: the script exits 2 if the text to mutate is not found exactly once.
3. Tests never call a paid service or send real email. Turnstile uses Cloudflare's always-pass test keys on both sides: every test build sets `VITE_TURNSTILE_SITE_KEY=1x00000000000000000000AA` (the public always-pass site key, B3 runbook; never the GitHub variable, which holds the real key for `main`, E10) and the Worker gets `TURNSTILE_SECRET=1x0000000000000000000000000000000AA` in `.dev.vars`. No test calls Resend: the Worker never sends (B5), and every address a test writes is on the reserved domain `fixtures.invalid`, which no mail server accepts. Events are written in SQL (G20): until B8 step 2a's SQL functions and B8b's recipes exist, a test write creates no job at all. Once they exist, the `send_email` job runs in the Edge Function on `mop-dev`, and B5's `send_email` step (B5 step 4) checks the recipient's domain first: any `.invalid`, `.test` or `.example` address ends `skipped` with `error = 'reserved_domain'` and no call to Resend, whether `EMAIL_DRY_RUN=1` (B5 step 4a, until setup A3) is set or not (G14). So `test:e2e:live` stays runnable on `mop-dev` after setup A3. Proof once B5 step 4 lands: `bun run db:psql -- -c "select count(*) from email_messages where to_email like '%@fixtures.invalid' and status = 'sent'"` prints 0.
4. Tests never touch `mop-prod`. Each entry point checks the variable it actually connects with. `tests/db/global-setup.ts` (B2) guards the `db` project. `tests/fixtures/service.ts` refuses, before creating a client, any `SUPABASE_URL` whose host is not `<DEV_SUPABASE_PROJECT_REF>.supabase.co` (`hbokkmpgpqhrnemgsqra` today). `scripts/load-fixtures.ts` connects with `DEV_DB_URL`, so it refuses, before connecting, a URL whose user is not `postgres.<DEV_SUPABASE_PROJECT_REF>`, and after connecting refuses when `select value from settings where key = 'environment'` is `production`; both print `refused: not mop-dev` and exit 1. `tests/unit/service-guard.test.ts` and step 8's proof cover the two B4 guards. Because `mop-dev` is shared, every db test of this plan runs inside a transaction that is rolled back (`withRollback` from B2's harness in `tests/fixtures/db.ts`, over `DEV_DB_URL`), so nothing it writes survives. None of B4's database tests uses `committed(fn, cleanup)`: F22 allows committed mode only for B3's `tests/api`, B6's parallel invoice-number test and B8's claim, queue and cron tests, which need rows visible across connections; B4's tests need no such thing, so they all roll back. B4 creates no auth user (its tests never call B2's `createAuthUser` or `createStaffUser`). Rows that a transaction cannot cover (rows written over HTTP by the live specs, and the committed dataset of `fixtures:load`) are idempotent, marked by an email on `fixtures.invalid` and removed by `removeFixtureRows` over `DEV_DB_URL` (in `afterAll` for the live specs) (never by a supabase-js `delete`, which runs in its own transaction and is refused by `refuse_hard_delete`). The seed is never run with `--target prod` here (BLOCKED until launch, F17); tests that need a pristine database use a scratch schema on `mop-dev` or a throwaway cluster from the native PostgreSQL 18 (`initdb` in a temp folder; no pg_cron, pgmq or pg_net there). One writer at a time (G34): `scripts/e2e-coming-soon.ts`, `scripts/load-fixtures.ts`, the `E2E_DATASET=1` branch of `tests/e2e/global-setup.ts` and `live-forms.spec.ts` (from `beforeAll` to the end of its `afterAll`) each hold `select pg_advisory_lock(hashtext('mop-dev-tests'))` on one `pg` connection to `DEV_DB_URL` while they commit rows or flip the flag, through `holdDevLock()` in `tests/fixtures/dev-lock.ts`, and release it with `pg_advisory_unlock` at the end. `holdDevLock()` is a no-op when `MOP_DEV_LOCK_HELD=1`, which `e2e-coming-soon.ts` sets for the Playwright run it spawns, so a cleanup inside that run never waits on its parent's lock. In CI the `mop-dev` concurrency group serialises the same work.
5. External fonts are blocked in CI (`page.route` on `fonts.googleapis.com` and `fonts.gstatic.com`) so runs are deterministic and offline-tolerant. ASSUMED trade-off: layout can differ slightly from real fonts, so an `@overflow` subset runs against the real preview URL after deploy (step 10): `sweep.spec.ts` adds, per route, a second test titled `overflow <route> @overflow` that only loads the page and calls `expectNoOverflow`, and `collect(page)` installs the font blocker only when `E2E_TARGET` is not `url`. Once B17 self-hosts the fonts (G8, G-014) the blocker matches no request and the sweep itself runs on real fonts; the preview run stays as the check on the deployed build.
6. One flaky pass counts as a failure in CI (`failOnFlakyTests`), so a retry cannot hide a defect. ASSUMED: one retry only to collect a trace.
7. Free tier: Actions minutes are the budget (P-009). The plan aims for under 10 minutes per PR push; measured in step 10, not assumed.
8. Test data is deterministic (GQ-03). Factories take their clock from `tests/fixtures/clock.ts` (`FIXED_NOW = 2026-10-01T12:00:00Z`), their randomness from a seeded generator (`mulberry32(seed)`), and their ids from `deterministicUuid(namespace, n)`, so two runs produce the same rows and the same ids. No factory calls `Date.now()`, `Math.random()` or `crypto.randomUUID()` (a unit test greps the files). Every row a factory or the dataset inserts is marked by an agent or inquirer email on the reserved domain `fixtures.invalid`, so cleanup and counts never touch other rows.
9. The illustrative seed is the catalog baseline; the factories are for operational rows the seed does not hold (submissions in every workflow state and jobs here; invoices are B6's, G24). A factory writes through the service role and respects B2's rules: `rights_version`, `rights_confirmed_at` and `rights_ip_hash` are always set, and deleting goes through a transaction that sets `mop.retention = 'on'` because the hard-delete guard refuses anything else.
10. The caching contract is proved here in three parts (architecture 13, S52, F24, F25). (1) Memory layer: a database call counter wraps the injectable `db` client that `getPublicState(db)`, `getCatalog(db)` and the public request handler receive (F25 e). After warm-up, 1,000 public page and catalog requests move the counter only by state checks (at most one `public_state` call per 15 seconds of test time) and by one `public_catalog_snapshot` call per catalog version; a table read (`from`) on a public request is a failure, which is rule 1 (one read path) made executable, and so is any RPC name other than those two (search is the in-Worker index over the snapshot, F25 g, so a search moves no counter). The test reads only through the two RPCs; its single write is one `bump_catalog_version()` call (a version number on `mop-dev`, harmless and not rolled back), and its write-path probes send an invalid body so that no row is created. The key names of the raw `public_state()` RPC payload (`catalog_version`, `flags`, `coming_soon_global`, `coming_soon_markets`, `site`, `illustrative_content`) and of the snapshot (`redirects`, `slug_history` among them) are final (F25 b) and the test asserts them on `serviceClient().rpc(...)`; the object `getPublicState(db)` returns is B3's camelCase mapping (`catalogVersion`, `flags`, `comingSoonGlobal`, `comingSoonMarkets`, `site`, `illustrativeContent`) and the test asserts those names on it. (2) Query hydration: B3 owns it in `src/router.tsx`; B4 proves by an e2e test that a page load makes no catalog fetch (F25 f). (3) Edge layer: the Cache API works under local `bunx wrangler dev` (E16), so B4 proves it locally on the built artifact by reading the `x-mop-cache` header, miss then hit, with a random query string hitting the same entry, and that the stored Content-Security-Policy header is the same on a hit and a miss (F25 d, j); L1 confirms it on the custom domain and H1 measures the hit ratio with `pg_stat_statements` (E15). A write to the public keys of `settings` (`flags`, `coming_soon_global`, `site`, `environment`, `og_static`, G21), to `markets.coming_soon`, `redirects` or `slug_history` bumps `catalog_version` by B2's trigger (F25 a as narrowed by G21); other `settings` keys (channels, tokens) do not. So no code bumps it by hand and the only deliberate calls are the one above and the one in `edge-cache.spec.ts`; live and coming-soon runs set `CATALOG_VERSION_TTL_MS=0` so a flag flip is seen at once instead of within 15 seconds.
11. The performance budget has one source, `budget.json`: the three limits and the six page templates `"paths": ["/", "/properties", "property:first", "market:first", "/exposure", "/submit"]`. `lighthouseRoutes(mode)` imports that JSON and `scripts/lhci-urls.mjs` reads it, so there is one list. `tests/unit/perf-budget.test.ts` fails when `lighthouserc.json` asserts a looser limit than `budget.json` holds, when `lighthouserc.json` carries any `collect.url` of its own (the URLs are passed at run time), when `lighthouseRoutes("local")` does not resolve the same six templates, or when an assertion level is `warn` for a hard limit.

Events emitted: none. Permissions: none; test helpers use the `mop-dev` service key (from the environment, never committed) and never ship. Nothing in this plan needs R2: the seed runs with `--images skip` and the sweep reads bundled images (R2 is off, S50).
