## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs: the `mop-dev` project (ref `hbokkmpgpqhrnemgsqra`, E9) and a production-configured preview (same build as production, `MOP_ENV=production` catalog rules), the GitHub repository settings, the Cloudflare zone, Supabase projects.
Outputs: `scripts/harden/*` (runner plus checks, including `cache-probe.ts`, the proof of the caching contract), `docs/runbooks/incident.md`, `docs/runbooks/rotation.md`, `docs/runbooks/rollback.md`, `docs/runbooks/restore.md`, `docs/security.md` (what is protected and how), the sign-off report, fixes to whatever the checks find.
Invariants
1. Every checklist item has a proof that a person can re-run: a command with expected output, or a named manual check with an owner. "Looks fine" is not a proof.
2. Every new automated check is watched-fail: break the thing it guards, see the check red for the right reason, restore (global rule 2).
3. Findings are fixed in the slice that owns them; H1 does not patch features silently. Each fix is a commit that names the H1 item.
4. No production data touched. Restore rehearsal runs on a throwaway cluster from the native PostgreSQL 18 (`initdb` in a temp folder, E7), never against `mop-prod` and never in Docker (S50, P-038); Supabase's free plan allows only the two projects `mop-dev` and `mop-prod`, so there is no third cloud project to restore into (P-009 context).
5. A runbook is a proof, not prose: `scripts/harden/runbook-lint.mjs` fails a runbook that lacks a required heading or names a command, script or file that does not exist, and the incident runbook is walked once by a person who did not write it (manual item below).
6. Nothing new is paid for. If a check shows a limit is reached, the result is a decision row in PROJECT-STATE (G-011), not a plan upgrade.
7. The caching contract (architecture 13, S52, F24, F25) is proved here, not assumed: after warm-up a public page view or catalog read costs zero database queries beyond the state checks, public HTML is identical for every visitor, the never-cached list is never cached, the edge layer answers miss then hit (proved locally under `bunx wrangler dev`, where the Cache API works, E16, H1-40) and the edge hit ratio is 95 percent or better on the custom domain (confirmed at L1, H1-41). The database client is injectable (F25 e) and B4's counter test wraps it; H1 runs black box against a running Worker and counts real statements with `pg_stat_statements` on `mop-dev` (E15: readable through the session pooler with the database password). H1 reads only through `getPublicState` and `getCatalog`: no probe, drill or check in this slice queries a table on a visitor's behalf; the drills that write or read tables (retention, rotation, incident, RLS) use the service role against `mop-dev` as operators, never as a public read, and the incident drill waits for the 15 second state check before it asserts what a visitor sees. No check calls an outside API on a page view (rule 10): the gauges come from the scheduled script `usage.mjs` only, and admin routes are proved `no-store` (H1-40 mode `never`) and by the authorization matrix (H1-15).
Events emitted: none. Permissions: needs admin access to GitHub, Cloudflare, Supabase; runs from a developer machine and from CI.
