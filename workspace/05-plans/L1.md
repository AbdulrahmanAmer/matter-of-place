Proof, in order: `dig` and `curl` output for the cut-over; the render-gate result for production pages; the rehearsal timeline table; the week-one log with a signed day 7; the first Saturday audit report. The first real property depends on the business (an accepted submission and payment), so step 7 is BLOCKED until it exists and is reported as such, not faked.

## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs: `workspace/audits/harden-<date>.md` with no red row; production secrets; Namecheap and Cloudflare access; the Supabase `mop-prod` project; the Search Console and Bing accounts.
Outputs: production live, `docs/runbook-launch.md` (the sequence actually used, with times), `workspace/audits/launch-week-1.md` (daily log), decisions added to PROJECT-STATE (the operator writes them).
Invariants
1. Coming-soon honesty (S30): from the first request, production shows zero listings. `markets.coming_soon = true` for CA, NY and FL, `settings.coming_soon_global = true`, no illustrative seed on `mop-prod`, no `/property/` URL in the sitemap, and each empty page says what Matter of Place is and offers the signup with the market preselected.
2. No forced order between DNS and the deploy: the production Worker is deployed and verified on its `workers.dev` address first (it sends `X-Robots-Tag: noindex` there, B13), and only then attached to the domain.
3. Reversible cut-over: DNS records and TTLs are written down before change; the Worker rollback drill (H1-22) exists; the registrar stays Namecheap (S29) and only nameservers move.
4. Nothing is indexed or advertised until the coming-soon verification passes.
5. The 60-day human approval window (S23) starts on the launch date: `channel_settings.auto_after` is set to launch date plus 60 days by an audited edit on screen 20, `Feature = auto` only after that date, `Campaign` and `Reach` stay manual.
6. The audit loop is switched on only after a manual first audit succeeded (B14 step 8).
7. Free tier: launch adds no paid service. If a gauge reads 70 percent or more the response is a decision row (G-011).
Events emitted: none new. Permissions: CEO and admin role only for DNS, secrets, Settings, Automation; agents do not touch DNS or production secrets.

## Iterate loop (entry and rhythm)
1. Saturday morning: the audit robot writes the report and PRs (S27). Sunday: the CEO reads it.
2. Monday triage (30 minutes): pick the top three findings by score; the smallest becomes a PR review, the others become slice plans `workspace/05-plans/I-<n>.md` with the same nine-section structure.
3. Merge on green CI after human review; deploy is automatic on merge; the next Saturday's report shows the delta.
4. Monthly: read the gauges and decide any upgrade; quarterly: re-check P-009 numbers against vendors' pages and edit GOTCHAS.
5. Day 60: switch Feature-tier posts to automatic if the approval record is clean (S23), by an audited edit on screen 20.
6. Month two candidates already decided: Pinterest and LinkedIn adapters (S22, interface exists from B10), Stripe behind the existing `payments` state machine (S32), reel or carousel design revisions from real metrics.
7. Growth lane is finished after four consecutive Saturday reports and their PRs shipped (Part C).

## Risks and gotchas (link GOTCHAS ids)
- P-015: Git Bash rewrites arguments that begin with `/`; use `MSYS_NO_PATHCONV=1` and the `D:/` drive path for the render gate, or PowerShell.
- P-013: use absolute paths in launch scripts. P-008: JSON payloads via files, not inline Bash.
- G-009: history is append-only; the launch is a merge, never a force push.
- G-011 and P-009: the launch week is when traffic first tests the free limits. The Workers free plan CPU limit (10 ms) was probed in H1-30; check the real numbers on day 1.
- G-012: `deploy.yml` at the repository root.
- G-006: production secrets set only by name through the CLIs; nothing pasted into the repo or a chat.
- DNS: a DNSSEC mismatch at the registrar during a nameserver change is the classic outage; step 4b exists for that. Cloudflare Email Routing adds MX and SPF records on the apex; Resend uses the `send` subdomain, so they should coexist (ASSUMED, verify the SPF record has a single `v=spf1`).
- HSTS with `includeSubDomains` at launch is hard to undo; do not submit to the preload list until a month of stability (ASSUMED).
- Search Console shows "Excluded by noindex" for empty market pages and thin archive URLs; that is the design (B13), not an incident.
- Supabase free projects pause after 7 idle days; `mop-prod` gets traffic from the keep-warm cron, verified in the daily list. A paused production database turns signups into errors.
- Coming-soon collects personal data (email, market); privacy page and the double opt-in copy must be live before the first signup (B16, B5).
- Meta: posting stays disabled in production until the real token passes `scripts/meta-check.ts`, and every post stays human-approved for 60 days (S23).
- The first real property carries reputational risk; the owner previews the dossier and the generated assets before approval, and any asset the owner dislikes is rejected with a note (which is data for the next template revision).
