Invariants
1. Nothing in the browser holds a Supabase key (architecture 1). No grant to `anon` on any table, function or sequence; `authenticated` gets only what an RLS policy allows. Public reads go through the Worker with the service role.
2. Every table has RLS enabled, and a table without a policy for a role is closed to that role. Default privileges for new tables revoke everything from `anon` and `authenticated`, so a forgotten grant fails closed.
3. `audit_log`, and later `events` and `automation_revisions`, are append-only: a trigger raises on update and delete even for the service role.
4. Only these delete paths exist (GD-04): cascades from foreign keys, `admin` deleting `agent_keys` (architecture 3.7), and the retention job. Nothing else hard-deletes: a `before delete` trigger `refuse_hard_delete()` on `properties`, `stories`, `subscribers`, `submissions`, `inquiries`, `payments` and `campaigns` raises unless the transaction has set `mop.retention = 'on'` (`set_config('mop.retention', 'on', true)`, called only by B8's `retention` job and by test helpers). It binds the service role too, because RLS does not. Retiring content is soft: `archived_at` on `properties`, `stories` and `subscribers`.
5. A submission cannot reach `Invoice Issued` or later without `accepted_at`, and cannot reach `Scheduled` without a `payments` row whose status is `paid` or `waived` (S32). The transition graph is one function, mirrored by `src/domain/workflow.ts`, and a database test compares them.
6. `properties.editorial_state = 'published'` if and only if `published_at` is not null; `editorial_state = 'archived'` if and only if `archived_at` is not null (same rule on `stories`). Only `published` rows are ever public; `agent_review` is not. `hero_rank` and `featured_rank` are unique among non-null values. `properties.market_slug` and `region_slug` must agree (composite foreign key).
7. Markets are exactly `california`, `new-york`, `florida` (brand guardrail: no other market). `subscribers.markets` is a subset of those three.
8. `settings.catalog_version` increases by one on every change to published catalog content, and never on its own update.
9. Free tier: 500 MB (P-009). `analytics_events` is partitioned monthly and kept 13 months (architecture 10; this supersedes the earlier ASSUMED 6 months). At about 24 MB per 120,000 events (200 bytes a row) that is about 24 MB a month, so 13 months at that volume is about 310 MB, most of the free database. The number is data, not code: `retention_policies.analytics_events` can be lowered by an admin, and the health job (B14) warns at 70 % of the 500 MB line.
10. Optimistic locking (GD-01): `properties.version int not null default 1` is incremented by a `before update` trigger on every update, and the only write path for edits is `save_property(p_id, p_expected_version, p_patch jsonb)`, which raises SQLSTATE `40001` with message `version_conflict` (B7 maps it to HTTP 409) when `p_expected_version` differs from the stored one. `version` belongs to the admin row type (`PropertyRow`); the public `Property` payload never carries it (G-004 note in Risks).
11. Slugs (GD-02): once `published_at` is set, `properties.slug` cannot change (trigger `enforce_slug_immutable` raises `slug_immutable`, and a takedown keeps the slug reserved). Before publication a rename writes the old slug to `slug_history (slug pk, property_id, changed_at)`, and a new slug may not equal any `slug_history.slug` of another property. B3 serves a `301` from `slug_history` before `notFound()`; B13 keeps those slugs out of the sitemap.
12. Rights record (GP-03): every submission row carries `rights_version` (the licence-terms text version the agent accepted), `rights_confirmed_at` and `rights_ip_hash` (`sha256(RATE_LIMIT_SALT:ip)`, never a raw IP), all not null. The constant `currentRightsVersion` in `contracts.ts` is what B3 writes and the form displays. Takedown is a soft state: unpublish sets `editorial_state = 'archived'` and `archived_at`, the row and its slug stay, B13 answers `410 Gone` for it, and the reason is B7's `audit_log.note`.
13. Uploads (GQ-07): accepted types `image/jpeg`, `image/png`, `image/heic`, `image/webp`; 25 MB per file (26,214,400 bytes); at most 40 files per submission. The same numbers live in the `uploadLimits` constant of `contracts.ts`, in `[storage] file_size_limit` and the bucket MIME list, in check constraints on `submission_media`, and in a `before insert` trigger that refuses a 41st `submission_media` row for one `submission_id`. `scripts/variants.ts` accepts the four types and converts HEIC to JPEG before variants.
14. Migration headers (GD-07): every file in `supabase/migrations` opens with either a `-- down:` block (the SQL that undoes it, applied in production only as a new forward migration) or `-- irreversible: <reason>` (for example `alter type ... add value`). `tests/db/migration-headers.test.ts` fails a file with neither, including files later slices add.
15. Preview links (GG-07): `properties.preview_nonce uuid` is part of the signed preview token B7 mints (`<property_id>.<expires>.<hmac>`, 7 days, page served `noindex`); changing the nonce revokes every outstanding link. No table stores tokens.

Events emitted: none (B8 owns `events`). Permissions: architecture 3.7, encoded in `20261001090900_rls.sql` and tested as a matrix. Summary: select for every staff role; submissions decide by chief_editor and managing_editor; properties write by chief_editor, managing_editor, visual_editor; payments by managing_editor and admin; `decline_reasons` by chief_editor, media_ops, admin; team tables by admin.

New tables: `slug_history` select for staff, no write policy (written only by trigger); `redirects` select for staff, write by chief_editor, managing_editor, admin (ASSUMED); `retention_policies` select for staff, update by admin only, no insert or delete policy. `subject_requests` is B3's and follows the same fail-closed default.

The sketch's public `media` bucket is not created because photography lives in R2 (S11). No policy on `storage.objects` for `anon` or `authenticated`; signed URLs come from the service role.

## Risks and gotchas (link GOTCHAS ids)
- G-010: `docs/database/schema.sql` is the Lovable sketch. Only enum names are reused; columns, types and policies come from architecture 3. Deleting the file at step 14 removes the temptation.
- G-004: the rule now spans `supabase/migrations`, `src/db/types.ts`, `src/domain/*` and the Zod contracts. Update the G-004 entry when this lands: its `paths:` should name `supabase/migrations/**` instead of `docs/database/schema.sql`, and its proof should be the `gen:types` diff plus `enums.check.ts`.
- G-011 and P-009: pg_cron, partitions and the `submissions` bucket are free. `mop-dev` and `mop-prod` each pause after 7 idle days; `mop-prod` needs the keep-warm before launch (B8b). Storage 1 GB: submission photographs at 25 MB each fill it after about 40 full-size uploads, so B7 must move accepted photographs to R2 and delete the originals from the bucket.
- G-008: the Supabase CLI on Windows can emit CRLF. `gen-types.mjs` normalises; the postwrite hook rejects CRLF otherwise.
- bun 1.3 skips dependency install scripts unless the package is in `trustedDependencies`. `supabase` downloads its binary in a postinstall; without the entry `bunx supabase` may work while `node_modules/.bin/supabase` does not. The global CLI 2.98.2 is a fallback.
- The `service_role` key bypasses RLS: the matrix proves user roles, not the Worker. The Worker's own checks are tested in B3 and B7.
- The `audit_log` immutability trigger also blocks the service role by design; a wrong row is corrected with a new row.
- Cross-plan: B8 lists `events` under its own migration, but B3 emits events before B8 lands. B3's `emitEvent` stub bridges the gap. B8b must not create `decline_reasons`.
- UNPROVEN until step 12: Bun loading `src/data/*` with the asset-loader plugin (imports of `.jpg`). Fallback: a one-off `scripts/lib/data-snapshot.ts` generated with Vite's SSR build; record the choice.
- ASSUMED region `us-east-1` for both projects; a project's region cannot change later.
- GD-04: `refuse_hard_delete` also blocks test cleanup and manual fixes. Tests and the runbook wrap deletes in a transaction that sets `mop.retention = 'on'`; the setting is transaction-local, so nothing leaks. A wrong row is archived, not deleted.
- GD-01 and G-004: `version` exists in the table and in `PropertyRow`, and is deliberately absent from the public `Property` type and payload; the admin DTO in B7 carries it. The three-file rule holds because the public mapper (B3) lists fields explicitly, so a new column does not leak; the parity test in B3 would name a leaked `version`.
- GD-03: 13 months of analytics is about 310 MB at the assumed volume (invariant 9), so retention of `analytics_events` is the first line to lower if the free database passes 70 %. The `retention` job itself is B8's; here the policies are data and the guard is code.
- GP-04: re-encoding the original loses no pixels that matter but changes bytes, so `sha256` in `submission_media` (of the upload) differs from the sha8 in the R2 key (of the stripped file). Both are recorded; nothing compares them. Accepted photographs must pass through `stripExif` when B7 moves them from the `submissions` bucket to R2, and B9's render workflow must import the same helper; an original with GPS must never reach R2. UNPROVEN for HEIC until the fixture converts in step 13.
- GG-07: the signed preview link needs a signing secret (ASSUMED name `PREVIEW_SIGNING_SECRET`, Worker secret, added with B7) and a public route that serves the unpublished dossier with `noindex` and `private, no-store`. Neither is built in B2; B2 supplies the state, `preview_nonce` and the visibility rule.
- Cross-plan: B3's plan must write `rights_version`, `rights_confirmed_at`, `rights_ip_hash` in `create_submission`, and its `submissionMediaSchema` must import `uploadLimits` instead of repeating the numbers. B8's `retention` job must set `mop.retention = 'on'` and read `retention_policies`.
