## Goal and observed exit
Matter of Place is a product of Omnikom (S33). The entity name and registered address, the contact email and phone and the Instagram URL live in one place, `settings.site`, and every surface that names the business reads it: footer, contact page, legal page, privacy and terms pages, email footers, invoices, and the Organization structured data. Nothing is invented: a field that is not set renders no line at all. The same slice publishes the four legal pages the business needs before its first visitor: a privacy policy written for California (CCPA), Terms for Professionals, an accessibility statement, and the privacy request page behind the "Do Not Sell or Share" footer link.
Observed exit (completion map B16): "legal page shows the entity; no null contact lines". Proven as: `bun run scripts/set-site.ts --file scripts/fixtures/site.example.json` on `mop-dev`, then `curl -s https://pr-<n>.holy-meadow-4327.workers.dev/legal` (preview Worker, E2; `http://localhost:8080` for the local dev server) contains the entity and address and the sentence "Matter of Place is a product of Omnikom."; with an empty `settings.site` the same page contains neither `null` nor an empty paragraph; `curl -s https://<preview>/ | grep -o '"@type":"Organization"[^}]*'` shows `legalName` only when the entity is set. ## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs
- `settings.site` (architecture 3.1: "site = contact/legal/instagram"), value shape mirrors the existing `siteConfig` object so the static config is the local default:
  `{ contact: { email: string|null, phone: string|null, privacy_email: string|null }, legal: { entity: string|null, address: string|null }, social: { instagram: string|null, x: string|null, linkedin: string|null } }` (the shape ruled in G23 and seeded by B2 with `contact.email` `hello@matterofplace.com` and `contact.privacy_email` `privacy@matterofplace.com`, the Zoho aliases of ASSUMED E19, and every other leaf null; `social.instagram` matches `siteConfig.social.instagram`; `contact.privacy_email` is optional, the mailbox printed on the privacy page and used for requests that cannot use the form, and falls back to `contact.email` when null, GP-01).
- Owner inputs setup A9 (entity name, registered address, contact email and phone, Instagram handle). They are inputs, not decisions; until they arrive, production has empty values and the site says only what is true.

Outputs
- `GET /api/public/site` returns that object plus one derived boolean `illustrativeContent`, both taken from the one `getPublicState(db)` payload (`site` and `illustrativeContent`; the RPC key is `illustrative_content`, true only when `settings.environment` is exactly `development` or `preview`, false for a missing row or any other value, and forced false by the Worker when `MOP_ENV` is `production`, F26 c), so it costs no second read; public by design because these values are printed on the site. It is edge cached through B3's `edgeCached` helper (`src/server/public/cache.ts`, key per architecture 13 rule 3 with kind `json`, no query string allowed, `x-mop-cache` and `x-catalog-version` headers added by that helper) and invalidated by `catalog_version`. The handler takes an injectable database client (F25 e) and reads `settings.site` from `getPublicState(db)` (architecture 13 rule 1, S52, F24) and never queries `settings` itself.
- `getSiteSettings(db)` for server code (emails, invoices, health) returns `getPublicState(db).site`, so it costs no database query while the 15 second memo is warm; `siteQuery()` for the site. The server render of the root loader calls `getSiteSettings` in process, with no network hop to `/api/public/site`, and the query hydration in `src/router.tsx` (owned by B3, F25 f; B4's e2e test proves a page load makes no catalog fetch) carries the site query to the browser, so the footer causes no second request on load.
- Pages: `/legal` (notices), `/privacy`, `/terms` (Terms for Professionals), `/accessibility`, `/privacy-request` (split, see below), footer and contact reading the query. The footer carries four links: Privacy, Terms for Professionals, Accessibility, and "Do Not Sell or Share" (to `/privacy#do-not-sell`, CCPA).
- `siteReadiness(db)` returns the list of missing production fields: `contact.email`, `legal.entity`, `legal.address` (phone and Instagram are optional).

Invariants
1. One source: `settings.site`. `siteConfig.contact`, `.legal` and `.social` stay only as the local-mode defaults (all null). `siteConfig.parentCompany = "Omnikom"` stays a code constant; it is a brand fact, not a setting.
2. No null lines: a value renders only when it is a non-empty string after trimming. Enforced by one helper `presentLines(...)` and tested with an all-null and an all-set fixture.
2a. Caching (architecture 13, F24): every public read of the legal identity goes through `getPublicState`; no page, route, email context or health check reads `settings.site` directly (B5's `resolveAdminRecipients` keeps its own read of `settings.notifications`, which is not public state). The legal pages, footer and contact page render identical HTML for every visitor (no cookie, no per-request value), so the edge caches them with the rest of the pages under kind `html`; an edit of `settings.site` bumps `catalog_version` through B2's trigger on `settings`, which fires for its public keys (`flags`, `coming_soon_global`, `site`, `environment`, `og_static`, G21), and every cache key changes. The Content-Security-Policy header with a page's script hashes is stored with that page's cache entry (B3 stores it, B17 computes it, F25 d), so these pages need nothing from this slice for it. A request-time failure of the database serves the last good state (rule 7), so the footer entity never blanks during an outage. `POST /api/public/subjects/request` is B3's and stays `no-store` (rule 6).
3. The public endpoint exposes only the `site` key, parsed through `siteSettingsSchema`, and the derived `illustrativeContent` boolean; other `settings` keys (`email`, `invoice`, `notifications`, `agent_daily_limits`, `environment` itself) never leave the server.
4. Writing `settings.site` is human-admin only (architecture 6: agents cannot change `settings`). The write is one SQL function that updates the row and writes `audit_log` in one transaction; B2's trigger on `settings` bumps `catalog_version` in that same transaction because `site` is a public key (G21), so cached pages refresh within 15 seconds and this function never bumps the version by hand. Before screen 24 exists, `scripts/set-site.ts` calls it with the service role, `p_actor` null, `p_actor_kind` `human` (B2's `actor_kind` enum has only `human` and `agent`) and `p_note` `script: set-site`.
5. Copy never claims what is not known: no governing law, no registered-office wording, no licence numbers unless supplied. The legal pages are drafts written in plain sentences and are UNPROVEN legally until the lawyer reads them (HARDEN gate).
6. The illustrative-content paragraph on `/legal` appears only where illustrative content can appear (dev and preview). Production shows no illustrative property, ever (S30), so the sentence "Every property ... is fictional" would be false there. It follows `illustrativeContent` from the site query: false when `settings.environment` is missing or any value other than `development` or `preview`, and always false when `MOP_ENV` is `production` (F26 c); the paragraph then does not render. `legal-pages.test.tsx` renders `/legal` with `illustrativeContent: true` (paragraph present) and `false` (paragraph absent).
7. Legal versions are one constant: `legalVersions = { privacy, terms }` (ISO dates) in `src/config/site.ts`. `legalVersions.terms` is the value B3's submission service writes to `submissions.rights_version` (it passes `currentRightsVersion` to `create_submission` when an agent confirms rights, F9, GP-03), and the submission form (this slice, `src/components/forms/submit/steps.tsx`) links `/terms#rights-to-photographs` from that confirmation (GP-05). Editing terms copy without bumping the constant is caught by `legal-pages.test.tsx`: it renders `/terms`, takes the text content, hashes it with `node:crypto` sha256 and requires it to equal the entry for `legalVersions.terms` in `tests/unit/fixtures/legal-hashes.json` (a map from terms version to hash; a copy change adds a new version and a new entry, and an existing entry is never edited). The same file asserts `currentRightsVersion === legalVersions.terms`.
8. The California notices state only what is true of the build: no sale of personal information, no sharing for cross-context behavioural advertising, no sensitive personal information collected, retention periods equal to the ones enforced by B8's `retention` job (declined submission photographs 90 days, inquiries anonymised after 24 months, details of people who submitted a property anonymised 24 months after their last request (S55), privacy requests 24 months, raw analytics events 90 days and daily totals without any personal data 13 months (ruling H16), unconfirmed newsletter signups deleted after 30 days, email addresses cleared from sent-message and delivery records after 90 days, hashed IP addresses in rate-limit records deleted after 25 hours; audit records kept; G16), and request response within 45 days. The page reads the periods from `retentionPeriods` in `src/domain/retention.ts`, whose keys are the `retention_policies` row keys; `legal-pages.test.tsx` asserts the rendered numbers equal that constant, and `tests/db/settings-site.db.test.ts` asserts, key by key, that the constant equals the `retention_policies.keep_for` row of the same key on `mop-dev` (never a row count, G43). Each row is seeded by the slice that creates its table (G43): B2 seeds `declined_submission_media`, `inquiries_anonymise`, `analytics_events` and `unconfirmed_subscribers` (B2 creates `subscribers`); B3 seeds `rate_limits` and `subject_requests` (with `webhook_receipts`, which the page does not print) in `20261001100000_public_write_functions.sql`; B5 seeds `email_pii` because B5 creates `email_messages` and `email_events` (G48); the functions that enforce them are B8 step 8a's, run by B8's daily `retention` job (`src/server/jobs/system/retention.ts`), except `rate_limits`, which B8's `prune` job (`src/server/jobs/system/prune.ts`) deletes through `retention_delete_rows('rate_limits')`, so a number on the page that differs from the enforced policy fails a test. UNPROVEN legally until the lawyer reads it.
9. Every legal page is prose: `h1`, then `h2` sections, no popup, no cookie wall, no modal. The accessibility page describes only checks that have run (axe on every route, H1-28) and names manual checks as pending until H1 signs them.
10. Wording is calm, brief, no em dashes: footer line "A product of Omnikom."; legal sentence "Matter of Place is a product of Omnikom." A unit test asserts `t.footer.line` contains `siteConfig.parentCompany`, so the two cannot drift apart.

Terms and privacy: split. Reasons, all concrete: the Meta app review for B10 needs a stable public privacy URL and data-deletion instructions; Search Console, Resend and Turnstile ask for one; the footer already labels them separately but points both at anchors of one page; a privacy policy that names processors is long enough to deserve its own page. `/legal` keeps the notices (representation, editorial independence, company). Old `/legal#privacy` and `/legal#terms` anchors redirect to the new pages (ASSUMED A19). A fragment never reaches the server, so the redirect runs in the browser: `src/routes/_site.legal.tsx` runs one `useEffect` after hydration that reads `window.location.hash` and, for `#privacy`, calls `navigate({ to: "/privacy", replace: true })`, for `#terms`, `navigate({ to: "/terms", replace: true })`; any other hash or none leaves `/legal` as it is. Nothing is fetched and nothing can fail beyond a visitor without JavaScript staying on `/legal`, which links both pages. `/accessibility` is its own page for the same reason (a stable URL for the a11y contact and for procurement checks). The request page is `/privacy-request` and not `/privacy/request` on purpose: with `_site.privacy.tsx` present, TanStack's file router would make `_site.privacy.request.tsx` a child that needs an `Outlet`.

Events emitted: none (settings edits are audit rows and a `catalog_version` bump, not catalog events).

## Risks and gotchas (link GOTCHAS ids)
- G-004: the `settings.site` keys, `src/domain/settings.ts` and the API JSON are one shape; change together.
- G-005: routes read the site through `queries.ts` and `services`; only `data/exposure.ts` and `data/faq.ts` may be imported directly.
- G-003: new pages pass bare titles; `pageHead` adds the suffix.
- G-007: page CSS uses tokens; new legal pages reuse `.copy-page` and `.section-block`, no new hex.
- G-011: no new service; the public route is one more cached read on the free Worker (P-009: 100k requests per day; the footer query is cached five minutes in the browser).
- The layout loads the site on every page. If the edge cache misses, each first paint adds one API call; the cache key is `catalog_version`, so a settings edit refreshes everything at once.
- The address is one string, so `PostalAddress.streetAddress` is loose structured data. UNPROVEN in Google's Rich Results test until B13; if it warns, split the address into street, city, region, postcode with the same G-004 discipline.
- Privacy copy names processors and retention periods. The retention numbers on the page are the `retention_policies` rows (B2, B3 and B5, each seeding the rows of the tables it creates, G16, G43) held in `retentionPeriods`: declined submission photographs 90 days, inquiries anonymised after 24 months, submitter details anonymised 24 months after the last request (S55), privacy requests 24 months, raw analytics events 90 days and daily totals 13 months (ruling H16), unconfirmed signups 30 days, email addresses on message records 90 days, hashed IP addresses in rate limits 25 hours, audit records kept. An admin may lower the analytics period (B2); the page does not follow such a change by itself, so lowering it is a copy change plus the constant, and the db test on `mop-dev` only proves the seeded values. A lawyer must confirm before launch. UNPROVEN legally. The consent notice for GA4 is B3b's (GP-02; gtag.js only, there is no Tag Manager container, G41); this page describes it and must not say more than it does. Whether GA4 with Google signals off counts as "sharing" under CCPA is a legal question: the page says nothing is shared only while B13 keeps `allow_google_signals` and ad personalisation off, and the lawyer confirms. UNPROVEN.
- GP-01: the 45-day clock, the receipt email and fulfilment live outside this slice (B3 route, B3 `subject_requests` from migration `20261001100000_public_write_functions.sql`, B7 screen 25). Receipt is acknowledged automatically (G29): B3's `create_subject_request`, re-created by B8 step 2a, writes the event `subject_request.received` with `{ request_id, kind }` in the same transaction as the row, and B8b's recipe rows `send_subject_ack` (B5 template `subject_ack`, recipient `requester`) and `notify_admin_subject` mail the requester and alert staff; a failed send is retried by B8's job backoff and a dead job shows on screen 16, so the privacy page's "We confirm receipt by email" depends on those slices and step 6 proves the event row. The page promises "within 45 days"; if B3 or B7 slips, the promise is untested, so HARDEN should submit one request end to end before launch.
- GP-05: the refund sentences state the business rule from the sweep (declined never charged, accepted then withdrawn after publication not refunded). The lawyer decides whether it is enforceable; B6's invoice text must agree.
- GP-07: the statement lists only checks that have run. A false claim of conformance is worse than a short page; do not add a conformance level until H1-28 and the manual keyboard and screen reader pass are signed.
- Renaming a heading changes anchors other pages link to (`#do-not-sell`); the heading test guards it.
- The sentence "Matter of Place is a product of Omnikom." replaces "An Omnikom company" everywhere. Tech-stack 2 says the CEO's lawyer may prefer either form; changing it later is one string plus the test.
