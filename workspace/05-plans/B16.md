## Goal and observed exit
Matter of Place is a product of Omnikom (S33). The entity name and registered address, the contact email and phone and the Instagram URL live in one place, `settings.site`, and every surface that names the business reads it: footer, contact page, legal page, privacy and terms pages, email footers, invoices, and the Organization structured data. Nothing is invented: a field that is not set renders no line at all. The same slice publishes the four legal pages the business needs before its first visitor: a privacy policy written for California (CCPA), Terms for Professionals, an accessibility statement, and the privacy request page behind the "Do Not Sell or Share" footer link.
Observed exit (completion map B16): "legal page shows the entity; no null contact lines". Proven as: `bun run scripts/set-site.ts --file scripts/fixtures/site.example.json` on `mop-dev`, then `curl -s https://<preview>/legal` contains the entity and address and the sentence "Matter of Place is a product of Omnikom."; with an empty `settings.site` the same page contains neither `null` nor an empty paragraph; `curl -s https://<preview>/ | grep -o '"@type":"Organization"[^}]*'` shows `legalName` only when the entity is set. Legal pages proof: `/privacy`, `/terms` and `/accessibility` return 200 with exactly the headings listed under Files; every page's footer holds a link "Do Not Sell or Share" that resolves to `/privacy#do-not-sell`; the request page posts to `POST /api/public/subjects/request` and shows the confirmation.

## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs
- `settings.site` (architecture 3.1: "site = contact/legal/instagram"), value shape mirrors the existing `siteConfig` object so the static config is the local default:
  `{ contact: { email: string|null, phone: string|null, privacy_email: string|null }, legal: { entity: string|null, address: string|null }, social: { instagram: string|null, x: string|null, linkedin: string|null } }` (ASSUMED `social.instagram`, matching `siteConfig.social.instagram`; `contact.privacy_email` is optional, the mailbox printed on the privacy page and used for requests that cannot use the form, and falls back to `contact.email` when null, GP-01).
- Owner inputs A9 (entity name, registered address, contact email and phone, Instagram handle). They are inputs, not decisions; until they arrive, production has empty values and the site says only what is true.

Outputs
- `GET /api/public/site` returns that object plus one derived boolean `illustrative_content` (true unless `settings.environment` is `production`, B3b), public by design because these values are printed on the site. It is edge cached through B3's `edgeCached` helper (`src/server/public/cache.ts`) and invalidated by `catalog_version`.
- `getSiteSettings(db)` for server code (emails, invoices, health), `siteQuery()` for the site.
- Pages: `/legal` (notices), `/privacy`, `/terms` (Terms for Professionals), `/accessibility`, `/privacy-request` (split, see below), footer and contact reading the query. The footer carries four links: Privacy, Terms for Professionals, Accessibility, and "Do Not Sell or Share" (to `/privacy#do-not-sell`, CCPA).
- `siteReadiness(db)` returns the list of missing production fields: `contact.email`, `legal.entity`, `legal.address` (phone and Instagram are optional).

Invariants
1. One source: `settings.site`. `siteConfig.contact`, `.legal` and `.social` stay only as the local-mode defaults (all null). `siteConfig.parentCompany = "Omnikom"` stays a code constant; it is a brand fact, not a setting.
2. No null lines: a value renders only when it is a non-empty string after trimming. Enforced by one helper `presentLines(...)` and tested with an all-null and an all-set fixture.
3. The public endpoint exposes only the `site` key, parsed through `siteSettingsSchema`, and the derived `illustrative_content` boolean; other `settings` keys (`email`, `invoice`, `notifications`, `agent_daily_limits`, `environment` itself) never leave the server.
4. Writing `settings.site` is human-admin only (architecture 6: agents cannot change `settings`). The write is one SQL function that updates the row, writes `audit_log` and bumps `catalog_version` in one transaction, so cached pages refresh. Before screen 24 exists, `scripts/set-site.ts` calls it with the service role and actor null, note `script`.
5. Copy never claims what is not known: no governing law, no registered-office wording, no licence numbers unless supplied. The legal pages are drafts written in plain sentences and are UNPROVEN legally until the lawyer reads them (HARDEN gate).
6. The illustrative-content paragraph on `/legal` appears only where illustrative content can appear (dev and preview). Production shows no illustrative property, ever (S30), so the sentence "Every property ... is fictional" would be false there. It follows `illustrative_content` from the site query; if B3b has not landed the value is true whenever `settings.environment` is absent, so the paragraph stays as it is today.
7. Legal versions are one constant: `legalVersions = { privacy, terms }` (ISO dates) in `src/config/site.ts`. `legalVersions.terms` is the value B2 stores in `submissions.rights_version` when an agent confirms rights (GP-03), and the submission form (B3b) links `/terms` from that confirmation (GP-05). Editing terms copy without bumping the constant is caught by a test that hashes `terms.tsx` text against the recorded hash.
8. The California notices state only what is true of the build: no sale of personal information, no sharing for cross-context behavioural advertising, no sensitive personal information collected, retention periods equal to the ones enforced by B8's `retention` job (declined submission photographs 90 days, inquiries anonymised after 24 months, analytics 13 months; audit records kept), and request response within 45 days. A number on the page that differs from `retention_policies` fails the build test (`legal-pages.test.tsx` reads the same seed constants). UNPROVEN legally until the lawyer reads it.
9. Every legal page is prose: `h1`, then `h2` sections, no popup, no cookie wall, no modal. The accessibility page describes only checks that have run (axe on every route, H1-28) and names manual checks as pending until H1 signs them.
10. Wording is calm, brief, no em dashes: footer line "A product of Omnikom."; legal sentence "Matter of Place is a product of Omnikom." A unit test asserts `t.footer.line` contains `siteConfig.parentCompany`, so the two cannot drift apart.

Terms and privacy: split. Reasons, all concrete: the Meta app review for B10 needs a stable public privacy URL and data-deletion instructions; Search Console, Resend and Turnstile ask for one; the footer already labels them separately but points both at anchors of one page; a privacy policy that names processors is long enough to deserve its own page. `/legal` keeps the notices (representation, editorial independence, company). Old `/legal#privacy` and `/legal#terms` anchors are dropped without redirects because the site has not launched (S30). ASSUMED. `/accessibility` is its own page for the same reason (a stable URL for the a11y contact and for procurement checks). The request page is `/privacy-request` and not `/privacy/request` on purpose: with `privacy.tsx` present, TanStack's file router would make `privacy.request.tsx` a child that needs an `Outlet`.

Events emitted: none (settings edits are audit rows and a `catalog_version` bump, not catalog events).

## Risks and gotchas (link GOTCHAS ids)
- G-004: the `settings.site` keys, `src/domain/settings.ts` and the API JSON are one shape; change together.
- G-005: routes read the site through `queries.ts` and `services`; only `data/exposure.ts` and `data/faq.ts` may be imported directly.
- G-003: new pages pass bare titles; `pageHead` adds the suffix.
- G-007: page CSS uses tokens; new legal pages reuse `.copy-page` and `.section-block`, no new hex.
- G-011: no new service; the public route is one more cached read on the free Worker (P-009: 100k requests per day; the footer query is cached five minutes in the browser).
- The layout loads the site on every page. If the edge cache misses, each first paint adds one API call; the cache key is `catalog_version`, so a settings edit refreshes everything at once.
- The address is one string, so `PostalAddress.streetAddress` is loose structured data. UNPROVEN in Google's Rich Results test until B13; if it warns, split the address into street, city, region, postcode with the same G-004 discipline.
- Privacy copy names processors and retention periods. The retention numbers (inquiries and submissions kept while the conversation or review is open, removed on request) come from the current text; a lawyer must confirm before launch. UNPROVEN legally. The consent notice for GA4 and Tag Manager is B3b's (GP-02); this page describes it and must not say more than it does. Whether GA4 with Google signals off counts as "sharing" under CCPA is a legal question: the page says nothing is shared only while B13 keeps `allow_google_signals` and ad personalisation off, and the lawyer confirms. UNPROVEN.
- GP-01: the 45-day clock, the confirmation email and fulfilment live outside this slice (B3 route, B2 `subject_requests`, B7 screen 25). The page promises "within 45 days"; if B3 or B7 slips, the promise is untested, so HARDEN should submit one request end to end before launch.
- GP-05: the refund sentences state the business rule from the sweep (declined never charged, accepted then withdrawn after publication not refunded). The lawyer decides whether it is enforceable; B6's invoice text must agree.
- GP-07: the statement lists only checks that have run. A false claim of conformance is worse than a short page; do not add a conformance level until H1-28 and the manual keyboard and screen reader pass are signed.
- Renaming a heading changes anchors other pages link to (`#do-not-sell`); the heading test guards it.
- The sentence "Matter of Place is a product of Omnikom." replaces "An Omnikom company" everywhere. Tech-stack 2 says the CEO's lawyer may prefer either form; changing it later is one string plus the test.
