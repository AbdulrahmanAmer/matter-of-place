## Goal and observed exit
Matter of Place is a product of Omnikom (S33). The entity name and registered address, the contact email and phone and the Instagram URL live in one place, `settings.site`, and every surface that names the business reads it: footer, contact page, legal page, privacy and terms pages, email footers, invoices, and the Organization structured data. Nothing is invented: a field that is not set renders no line at all. The same slice publishes the four legal pages the business needs before its first visitor: a privacy policy written for California (CCPA), Terms for Professionals, an accessibility statement, and the privacy request page behind the "Do Not Sell or Share" footer link.
Observed exit (completion map B16): "legal page shows the entity; no null contact lines". Proven as: `bun run scripts/set-site.ts --file scripts/fixtures/site.example.json` on `mop-dev`, then `curl -s https://pr-<n>.holy-meadow-4327.workers.dev/legal` (preview Worker, E2; `http://localhost:8080` for the local dev server) contains the entity and address and the sentence "Matter of Place is a product of Omnikom."; with an empty `settings.site` the same page contains neither `null` nor an empty paragraph; `curl -s https://<preview>/ | grep -o '"@type":"Organization"[^}]*'` shows `legalName` only when the entity is set. Legal pages proof: `/privacy`, `/terms` and `/accessibility` return 200 with exactly the headings listed under Files; every page's footer holds a link "Do Not Sell or Share" that resolves to `/privacy#do-not-sell`; the request page posts to `POST /api/public/subjects/request` and shows the confirmation.

## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs
- `settings.site` (architecture 3.1: "site = contact/legal/instagram"), value shape mirrors the existing `siteConfig` object so the static config is the local default:
  `{ contact: { email: string|null, phone: string|null, privacy_email: string|null }, legal: { entity: string|null, address: string|null }, social: { instagram: string|null, x: string|null, linkedin: string|null } }` (ASSUMED `social.instagram`, matching `siteConfig.social.instagram`; `contact.privacy_email` is optional, the mailbox printed on the privacy page and used for requests that cannot use the form, and falls back to `contact.email` when null, GP-01).
- Owner inputs A9 (entity name, registered address, contact email and phone, Instagram handle). They are inputs, not decisions; until they arrive, production has empty values and the site says only what is true.

Outputs
- `GET /api/public/site` returns that object plus one derived boolean `illustrativeContent`, both taken from the one `getPublicState(db)` payload (`site` and `illustrativeContent`; the RPC key is `illustrative_content`, true only when `settings.environment` is exactly `development` or `preview`, false for a missing row or any other value, and forced false by the Worker when `MOP_ENV` is `production`, F26 c), so it costs no second read; public by design because these values are printed on the site. It is edge cached through B3's `edgeCached` helper (`src/server/public/cache.ts`, key per architecture 13 rule 3 with kind `json`, no query string allowed, `x-mop-cache` and `x-catalog-version` headers added by that helper) and invalidated by `catalog_version`. The handler takes an injectable database client (F25 e) and reads `settings.site` from `getPublicState(db)` (architecture 13 rule 1, S52, F24) and never queries `settings` itself.
- `getSiteSettings(db)` for server code (emails, invoices, health) returns `getPublicState(db).site`, so it costs no database query while the 15 second memo is warm; `siteQuery()` for the site. The server render of the root loader calls `getSiteSettings` in process, with no network hop to `/api/public/site`, and the query hydration in `src/router.tsx` (owned by B3, F25 f; B4's e2e test proves a page load makes no catalog fetch) carries the site query to the browser, so the footer causes no second request on load.
- Pages: `/legal` (notices), `/privacy`, `/terms` (Terms for Professionals), `/accessibility`, `/privacy-request` (split, see below), footer and contact reading the query. The footer carries four links: Privacy, Terms for Professionals, Accessibility, and "Do Not Sell or Share" (to `/privacy#do-not-sell`, CCPA).
- `siteReadiness(db)` returns the list of missing production fields: `contact.email`, `legal.entity`, `legal.address` (phone and Instagram are optional).

Invariants
1. One source: `settings.site`. `siteConfig.contact`, `.legal` and `.social` stay only as the local-mode defaults (all null). `siteConfig.parentCompany = "Omnikom"` stays a code constant; it is a brand fact, not a setting.
2. No null lines: a value renders only when it is a non-empty string after trimming. Enforced by one helper `presentLines(...)` and tested with an all-null and an all-set fixture.
2a. Caching (architecture 13, F24): every public read of the legal identity goes through `getPublicState`; no page, route, email context or health check reads `settings.site` directly (B5's `resolveAdminRecipients` keeps its own read of `settings.notifications`, which is not public state). The legal pages, footer and contact page render identical HTML for every visitor (no cookie, no per-request value), so the edge caches them with the rest of the pages under kind `html`; a settings edit bumps `catalog_version` through B2's trigger on `settings` and every key changes. The Content-Security-Policy header with a page's script hashes is stored with that page's cache entry (B3 stores it, B17 computes it, F25 d), so these pages need nothing from this slice for it. A request-time failure of the database serves the last good state (rule 7), so the footer entity never blanks during an outage. `POST /api/public/subjects/request` is B3's and stays `no-store` (rule 6).
3. The public endpoint exposes only the `site` key, parsed through `siteSettingsSchema`, and the derived `illustrativeContent` boolean; other `settings` keys (`email`, `invoice`, `notifications`, `agent_daily_limits`, `environment` itself) never leave the server.
4. Writing `settings.site` is human-admin only (architecture 6: agents cannot change `settings`). The write is one SQL function that updates the row and writes `audit_log` in one transaction; B2's trigger on `settings` bumps `catalog_version` in that same transaction (F25 a), so cached pages refresh within 15 seconds and this function never bumps the version by hand. Before screen 24 exists, `scripts/set-site.ts` calls it with the service role, `p_actor` null, `p_actor_kind` `human` (B2's `actor_kind` enum has only `human` and `agent`) and `p_note` `script: set-site`.
5. Copy never claims what is not known: no governing law, no registered-office wording, no licence numbers unless supplied. The legal pages are drafts written in plain sentences and are UNPROVEN legally until the lawyer reads them (HARDEN gate).
6. The illustrative-content paragraph on `/legal` appears only where illustrative content can appear (dev and preview). Production shows no illustrative property, ever (S30), so the sentence "Every property ... is fictional" would be false there. It follows `illustrativeContent` from the site query: false when `settings.environment` is missing or any value other than `development` or `preview`, and always false when `MOP_ENV` is `production` (F26 c); the paragraph then does not render. `legal-pages.test.tsx` renders `/legal` with `illustrativeContent: true` (paragraph present) and `false` (paragraph absent).
7. Legal versions are one constant: `legalVersions = { privacy, terms }` (ISO dates) in `src/config/site.ts`. `legalVersions.terms` is the value B2 stores in `submissions.rights_version` when an agent confirms rights (GP-03), and the submission form (this slice, `src/components/forms/submit/steps.tsx`) links `/terms#rights-to-photographs` from that confirmation (GP-05). Editing terms copy without bumping the constant is caught by `legal-pages.test.tsx`: it renders `/terms`, takes the text content, hashes it with `node:crypto` sha256 and requires it to equal the entry for `legalVersions.terms` in `tests/unit/fixtures/legal-hashes.json` (a map from terms version to hash; a copy change adds a new version and a new entry, and an existing entry is never edited). The same file asserts `currentRightsVersion === legalVersions.terms`.
8. The California notices state only what is true of the build: no sale of personal information, no sharing for cross-context behavioural advertising, no sensitive personal information collected, retention periods equal to the ones enforced by B8's `retention` job (declined submission photographs 90 days, inquiries anonymised after 24 months, privacy requests 24 months, analytics 13 months; audit records kept), and request response within 45 days. The page reads the periods from `retentionPeriods` in `src/domain/retention.ts`; `legal-pages.test.tsx` asserts the rendered numbers equal that constant, and `tests/db/settings-site.db.test.ts` asserts the constant equals the `retention_policies.keep_for` rows on `mop-dev` (B2 seeds `declined_submission_media`, `inquiries_anonymise`, `analytics_events`; B3 seeds `subject_requests`), so a number on the page that differs from the enforced policy fails a test. UNPROVEN legally until the lawyer reads it.
9. Every legal page is prose: `h1`, then `h2` sections, no popup, no cookie wall, no modal. The accessibility page describes only checks that have run (axe on every route, H1-28) and names manual checks as pending until H1 signs them.
10. Wording is calm, brief, no em dashes: footer line "A product of Omnikom."; legal sentence "Matter of Place is a product of Omnikom." A unit test asserts `t.footer.line` contains `siteConfig.parentCompany`, so the two cannot drift apart.

Terms and privacy: split. Reasons, all concrete: the Meta app review for B10 needs a stable public privacy URL and data-deletion instructions; Search Console, Resend and Turnstile ask for one; the footer already labels them separately but points both at anchors of one page; a privacy policy that names processors is long enough to deserve its own page. `/legal` keeps the notices (representation, editorial independence, company). Old `/legal#privacy` and `/legal#terms` anchors are dropped without redirects because the site has not launched (S30). ASSUMED. `/accessibility` is its own page for the same reason (a stable URL for the a11y contact and for procurement checks). The request page is `/privacy-request` and not `/privacy/request` on purpose: with `privacy.tsx` present, TanStack's file router would make `privacy.request.tsx` a child that needs an `Outlet`.

Events emitted: none (settings edits are audit rows and a `catalog_version` bump, not catalog events).
