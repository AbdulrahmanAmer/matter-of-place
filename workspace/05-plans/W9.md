# W9: a request, end to end

The operator, 2026-10-15, after the first real submission (Fairfield, California, The Feature; the agent's address
bounced and nothing in Admin showed it): "we need to be able to see from the admin dashboard if an email is wrong or
bounced", "make sure that our employees can pull the listing images on their own if the person submitting only sent the
listing link", "a sequence for what happens in the review process of a submitted property so we can make the team able
to drive things the right way", and "use SMTP for the agents as a small tool call that will check if the emails
actually exist before we send". Then: "yes go for it end to end".

A box is ticked only when the thing works and was observed working.

## A. A wrong address is caught and seen

- [ ] 1. **The address is checked before anything is sent.** A check (`scripts/workforce/email-check.ts`, and the same
  rule server-side for the forms) answers `ok | domain_has_no_mail | mailbox_refused | unknown` for an address: syntax,
  a common-typo domain list (gmial.com, hotmial.com, ...), the domain's MX records, and, where this machine can reach
  port 25, an SMTP probe (EHLO, MAIL FROM, RCPT TO, QUIT, never DATA) against the first MX. The submission, inquiry and
  signup forms suggest a fix for a typo domain before sending. A `mailbox_refused` address is never mailed; the request
  is flagged instead. Proof: unit tests for each outcome with a stubbed resolver and socket; a real run against a known
  good and a known bad address recorded in the PR.
- [ ] 2. **A bounce is visible where the person works.** The request page (Admin > Requests > a request) shows each
  email sent about it with its delivery state (sent, delivered, bounced, complained) from `email_messages` and
  `email_events`; a bounced one reads plainly ("The confirmation bounced: this mailbox does not exist") with a field to
  correct the address and resend. The same list for every email lives in a "Sent emails" screen (W7 item 1).
- [ ] 3. **A bounce reaches the team.** When Resend reports a bounce or complaint (the webhook already writes
  `email_events` and the suppression), the event `email.bounced` wakes the colleague who owns that source (listings:
  the Editor; inquiries: the Concierge), with the request, the failed address and the person's phone if given, so the
  owner proposes the next step (call, or ask for the right address) in Approvals, and Matter decides. Proof: the
  Fairfield bounce replayed as an event wakes the Editor and produces a proposal.

## B. Images without waiting for the submitter

- [ ] 4. **A colleague can pull the listing's photographs.** When a submission has a listing link or a photography link
  and its rights are confirmed (`rights_confirmed_at` is set; never otherwise), a colleague started by a person or
  Matter (W8 0e) downloads the images into the studio folder, keeps where each came from, and attaches them to the
  request as its media through the path uploads already use, so review and rendering can start. A link that needs a
  login, or a page whose images cannot be read, is said plainly to the team instead. Proof: one submission's images
  pulled from its link and visible on the request page.

## C. The review process, driven by the team

- [ ] 5. **The sequence, written and followed.** `workspace/05-plans/W9-review-sequence.md` names, for every state of a
  submission (Submitted, Under Review, Accepted or Declined, Awaiting Assets, Invoice Issued, Scheduled, Published,
  Distribution Active, Completed, Withdrawn): what starts it, which colleague owns it, what they check (the editorial
  standard, the rights, the address, the photographs), what Matter decides, what the operator approves, which email goes
  out and from which address, and what moves it on. The owning colleagues' briefs point to it, and a new submission
  wakes the Editor to begin it. Proof: the Fairfield submission walked from Submitted to Under Review by the team, with
  the steps visible in Admin.

## Order
1, 2, 3 (a wrong address can never again go unseen) → 5 (the sequence) → 4 (images).
