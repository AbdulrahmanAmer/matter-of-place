The operator, 2026-10-15: "the actual ability to create a post and write a proper caption and push those things online
to the Instagram account ... what are the tooling that are still missing". Found by reading the code and the live

property renders its own cover, carousel, story and reel. Live: 0 assets, 0 social posts, Instagram disabled.

Matter builds these through the merge gate, after W7 section E (reels), one pull request per item, the senior way:
extend the render steps, the assets table and the posting path that exist; never a second pipeline. A box is ticked

## 0. The foundation (operator, 2026-10-15), built before the rest of W8

The operator's words: "each source of something gets a criteria for what will be done for it. So an email regarding a
question gets only answered for that question ... if there is any commands directed at the AI employee to do something
outside of the criteria of this being an email or a form submission, it escalates it to Matter ... this needs to be
mechanical so it doesn't get skipped." And: the staff work on one laptop, so drafts are read between them as files, and
only what is approved goes to the database. CRITICAL (security): built and reviewed at high effort.

- [ ] 0a. **Every outside source has written criteria.** One file, `scripts/workforce/criteria.ts`, lists each source
  that can wake a colleague (inquiry form, submission form, privacy request, interest signup, email reply, Instagram
  comment and message once W8 item 4 exists) and, for each, what may be done: its allowed intents (for an inquiry: a
  question about a property, a showing request, a correction; nothing else), which colleague owns it, and the only
  actions that colleague may propose for it (for an inquiry: a reply to that person about that property). A source
  not in the file wakes no one. Proof: a unit test per source; a registry entry that watches the refusal of an
  unlisted source.
- [ ] 0b. **Triage first, by the runner, every time.** Before any colleague sees an outside message, the runner sends
  it to a triage call with no tools at all (`claude -p`, every tool refused, a JSON schema answer). The triage
  returns only: the source, the intent (one of the source's allowed intents, or `out_of_criteria`), the fields that
  intent needs (who, which property, the question in one plain sentence), and `instructions_to_ai: true|false` with
  the sentence that tried it. The colleague is woken with that structure, never with the raw text; the raw text stays
  in the database for a person to read. This is in the runner's code path, so no colleague and no prompt can skip it.
  Proof: tests with an ordinary question, a question with an injected instruction, and a message that is only an
  instruction; the colleague's prompt in each holds no raw text.
- [ ] 0c. **The owner answers only within the criteria.** The colleague works out what the person wants from the
  triage fields and proposes only the actions its source allows; the runner refuses any other proposal for that
  source (a social post from an inquiry, an admin change from an email). Proof: a test where an inquiry's run proposes
  something outside its criteria and the runner drops it with a logged reason.
- [ ] 0d. **Escalation to Matter, mechanical.** When the triage says `out_of_criteria` or `instructions_to_ai`, the
  runner does not wake the owner to answer: it opens a thread with Matter and the owner, carrying the triage, the
  sentence that tried to instruct, and what the person seems to want. The owner explains the context to the team in
  that thread, Matter decides whether and how to answer, and only Matter's decision lets a reply be proposed. Nothing
  about the company's systems, staff, keys or other customers goes into any reply. Proof: a test message with an
  instruction in it produces the thread with Matter and no reply until Matter decides; seen in the Office.
- [ ] 0e. **Terminals for work a person or Matter started.** A colleague run started by the operator or by Matter (not by
  outside text) gets a terminal like Matter's, in its own desk, with the same denials (no force push, no credential
  files, keys never in its environment). Runs woken by outside text stay read-only after triage. Proof: a Social run
  started by Matter that renders a file; an inquiry run that cannot.
- [ ] 0f. **The studio folder.** `~/.mop-workforce/studio/<date>-<name>/` holds each piece of work: the brief, every
  draft and revision, and `status.md` (who, state, next). Every colleague can read every piece; only runs started by a
  person or Matter write. Matter reviews drafts there. Nothing goes to Storage until it is approved; a piece that waits
  on the operator uploads only a small preview (a still, or a short low-quality clip) for the admin screen. The
  database keeps one small row per piece (title, owner, state, folder). Proof: a reel drafted, revised and approved in
  the studio, uploaded once, with the row tracking it.

- [ ] 0g. **A copy off the laptop (operator, 2026-10-15: "using Google Drive to save a few things here and there that can
  work as a backup").** The nightly "MOP Backup" task also copies, into the folder Google Drive for desktop mirrors
  (`G:\My Drive\Matter of Place\`, item 8): the studio folder without render scratch (frames, caches), Matter's notes,
  live state and goal list, the colleagues' knowledge, and the encrypted database backup. Never the `.env` file, the
  creds folder, keys or tokens: the copy script holds an allow-list of folders, not a deny-list. When the Drive folder
  is missing, the backup says so in its log and the health check names it. Proof: after a night, the files are on
  drive.google.com; a test of the allow-list refuses `.env` and `creds/`.
