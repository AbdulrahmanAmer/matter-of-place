## Goal and observed exit
Every Saturday morning a cloud routine runs `mop-auditor`: it measures performance, technical SEO, AEO and GEO, keyword coverage, channels, security drift and uptime, compares with the last report, checks each free-tier line against its limit, lists the paths visitors and crawlers asked for that returned 404, reads the weekly KPIs that B11 computes, probes the caching contract (hit ratio, never-cached list), writes `workspace/audits/YYYY-MM-DD.md`, and opens one pull request per proposed fix. It never merges, never deploys, never holds a credential that could.
Observed exit (completion map B14): "report in `workspace/audits/`; PR opened." Proof: a manual first run produces `workspace/audits/<date>.md` that passes `lint-report.mjs`, plus a pull request from a branch named `audit/<date>-<slug>` that passes the scope check; then the scheduled routine repeats it the next Saturday. The Part C growth exit needs four consecutive weeks; that is measured after launch, not in this slice.

## Contract (inputs, outputs, invariants, events emitted, permissions)
Inputs
- The live site (production once L1 is done, otherwise the newest preview at `https://pr-<n>.holy-meadow-4327.workers.dev` or the main Worker at `https://matter-of-place.holy-meadow-4327.workers.dev`, E2), `sitemap.xml`, `llms.txt`, robots.
- APIs: PageSpeed Insights, Search Console, GA4 Data API, Cloudflare GraphQL Analytics, Sentry stats, GitHub Actions usage, and our own `/api/admin/*` through one agent key for everything that lives in our database (jobs, channels, newsletter metrics, asset backlog, health, usage).
- The uptime monitor's read-only API (`UPTIME_API_KEY`, GS-04): monitor list, current status and 30-day uptime for the two monitored URLs. The monitor vendor is ASSUMED to be a free plan with a 5 minute interval (UptimeRobot free tier); the collector is one module returning `{ monitors: [{ url, interval_s, status, uptime_30d }] }`, so a different vendor changes one file.
- Unknown-path log (GG-02): rows in `analytics_events` with `event = 'not_found'`, written server side by `src/server/lib/not-found-log.ts` (path without query string, `data.referrer_host` only, no IP, no user agent), read through `GET /api/admin/audit/notfound`.
- The weekly KPI numbers (GG-03) through `GET /api/admin/audit/kpis?week_start=YYYY-MM-DD` (a Monday; default the last full week). The route calls B11's `collectWeeklyKpis(db, weekStart)` (`src/server/kpi/collect.ts`, SQL `kpi_weekly`, labels and definitions in `src/server/kpi/definitions.ts`); the week is B11's, Monday 00:00 to Sunday 24:00 in `America/New_York` (B11 invariant 12). This slice creates no KPI definition or computation of its own, so the email and the report cannot disagree.
- The cache probe (S52, F24): `workspace/audits/tools/cache.mjs` requests the public pages and catalog endpoints twice each, a random query string variant of each, and the never-cached routes, and reads only response headers (`x-mop-cache`, `x-catalog-version`, `Cache-Control`, `Set-Cookie`). It never calls the database and sends no cookie.
- The previous report (`workspace/audits/*.md` and its JSON sidecar) for deltas.
- `schedule_settings.audit` (screen 20; the row is B8b's seed, `cron 0 13 * * 6` UTC, `enabled = true`), read by `run-all.mjs` first through B8b's route `GET /api/admin/automation/schedule-settings/audit` with the agent key (scope `automation`, a read every role may make). If `enabled = false` the run prints the one line `skipped, disabled` to the routine's run log, writes no file, opens no pull request and exits 0, so an operator switch exists without editing the routine. If the read itself fails (network, 401, 5xx) the run goes on and records the schedule source under `not_measured`: the run is read-only, and the routine's own trigger is the second switch. The routine does not write `last_run_at` of the `audit` row (its key is read-only, invariant 3, and B8b's `automation.schedules_put` is `chief_editor, media_ops, admin`); the record of a run is the report pull request `audit/YYYY-MM-DD-report` and its sidecar, and screen 20 shows `last_run_at` empty for `audit`.

Outputs
- `workspace/audits/YYYY-MM-DD.md` (report) and `workspace/audits/data/YYYY-MM-DD.json` (machine sidecar of every number, used by the next run's deltas).
- Pull requests, one per fix, each on `audit/YYYY-MM-DD-<slug>`, plus one report PR `audit/YYYY-MM-DD-report`.
- Bank entries: anything that bit the run goes into `GOTCHAS.md` as a process entry with proof in the same PR (mop-auditor rule).

Report format (checked by `scripts/audit/lint-report.mjs`)
1. Title line `# Audit YYYY-MM-DD`, then a front block: run id, site URL, previous report path, tool versions, and which data sources were configured.
2. `## Summary` exactly five lines.
3. `## Scorecard` table: Performance (LCP, CLS, INP, score per key page from PSI lab data, plus a `field` column with the p75 LCP, CLS and INP per path over 7 days from `web_vitals` rows, read through `audit.health`; `Not measured` while there are none), Technical SEO, AEO and GEO, Keywords, Channels, Security, Uptime (30-day percent for `/` and `/api/public/markets`, monitor interval, alert contact confirmed), Caching (architecture 13: edge hit ratio of the probe's second pass against the 95 percent target, share of probed responses carrying `x-mop-cache`, `x-catalog-version` constant across the pass, query-string variants answered from the same key, every never-cached route answering `no-store`, no cached page carrying `Set-Cookie`, count of `stale` answers), each with value, previous, delta, status. On `workers.dev` and in `vite dev` the Cache API does nothing, so the edge ratio prints `Not measured` there (never `0`) and only the header checks run; it works under local `wrangler dev` (E16), where step 3 proves the probe, and the weekly ratio is real only on the custom domain (L1).
4. `## Free-tier gauges` table from P-009: line, used, limit, percent, previous percent, source, status. Lines: Workers requests per day and per month, R2 storage (`Not measured` while R2 is off, S50 and E8), Supabase database size, Supabase storage, Supabase egress (if measurable), Edge Function calls, Resend sends today and this month, Resend contacts, GitHub Actions minutes (approximate, see `collectors/github.mjs`), Sentry errors, Anthropic spend (always `Not measured`, reason "no producer: nothing records model token usage yet"; a line without a source is never `ok`). Status `ok` under 50 percent, `watch` 50 to 70, `DECISION` at 70 or more, `LIMIT` at 90 or more (GS-06: the same thresholds drive the daily health check, invariant 7).
5. `## KPIs` table (GG-03) with the eight weekly numbers of B11's `src/server/kpi/definitions.ts`: submissions received, acceptance rate, median time to decision, invoices issued and paid, properties published, posts by channel, newsletter net growth, inquiries per published property; each with value, previous week, delta, labels taken from `definitions.ts`. A value with no denominator prints as `collectWeeklyKpis` returns it (`0 of 0`, or "no published properties yet"), never a bare `0`.
6. `## Not found (404)` (GG-02): the 20 most requested unknown paths of the last 7 days with count and top referrer host, and whether each has a `redirects` row or a `slug_history` entry; a path asked at least 5 times with no redirect becomes a finding whose proposed fix is a `redirects` row (proposal only: it is data, not code).
7. `## Findings` ranked by `score = impact / effort` (impact 1 to 5, effort S=1, M=2, L=3). Each finding: id `A-YYYYMMDD-NN`, title, evidence (URL, metric, response excerpt or screenshot path), impact estimate, proposed fix with the file it touches, effort, score, PR link or "proposal only".
   Caching findings are ordinary findings: a hit ratio under 95 percent on the custom domain, a never-cached route answering without `no-store`, a cached page with `Set-Cookie`, a query string that changes the key, or a `stale` answer each become a finding whose proposed fix names the file (proposal only when it lies under `src/server/**`, invariant 2).
   A retention stall reported by `audit.health` (B8 GD-03: a policy whose overdue rows have survived 30 days of runs, or whose `last_run_at` is older than 2 days) is an ordinary finding, proposal only, naming the policy key and the overdue count.
8. `## Proposed changes` list linking each PR.
9. `## Not measured` every source that was not configured or failed, with the reason and what would unblock it. A red or missing source is reported, never hidden.
10. No em dash anywhere; calm wording; no fix that adds popups, gimmicks, keyword stuffing or copy outside the editorial voice (brand guard).

Invariants
1. Never deploys production. Production deploys run only from the `production` job of `deploy.yml` on a push to `main`, which happens only when a human merges. An audit pull request gets a `pr-<n>` preview Worker from the `preview` job of `deploy.yml` like any pull request (B1b); that is a preview on `workers.dev` against `mop-dev`, not a deploy of the site. The routine's GitHub identity can push branches and open pull requests, cannot dispatch workflows (no Actions write), cannot push a change under `.github/workflows/` (no Workflows permission, so GitHub refuses the push), cannot merge, cannot edit secrets, cannot touch branch protection. `main` requires a review from the CEO and passing checks (S27). GitHub branch protection is not available on this plan (P-028), so `audit-scope` is a job of `ci.yml` on audit pull requests: a red check the CEO reads before merging, not a hard gate. The production job never sees an `audit/` branch name; the enforcement is the human merge, `deploy.yml` running only after `ci.yml` passes on the same SHA, and nobody force-pushing (G-009); `CODEOWNERS` is documentation until protection exists.
2. Scope guard in CI: `scripts/audit/scope-check.mjs` takes the changed paths of a pull request from a branch starting with `audit/` (repository-root relative, because the git root is `E:/Matter Of Place`, G-012) and fails `audit-scope` on any path outside the allowed list. Allowed: `Matter Of Place Codebase/src/routes/**` except `Matter Of Place Codebase/src/routes/api/**` (head and copy), `Matter Of Place Codebase/src/lib/**`, `Matter Of Place Codebase/src/components/**`, `Matter Of Place Codebase/src/styles/**`, `Matter Of Place Codebase/public/**`, `Matter Of Place Codebase/docs/**`, `workspace/audits/**`, `GOTCHAS.md`. So `.github/**`, `Matter Of Place Codebase/supabase/**`, `Matter Of Place Codebase/wrangler.toml`, any `.env*`, `Matter Of Place Codebase/src/server/**`, `Matter Of Place Codebase/src/routes/api/**`, `.claude/**` and any path holding secrets or auth are refused. Anything outside is a "proposal only" finding.
3. Read-only on data: the auditor authenticates with an agent key whose role is `commercial` and whose scopes are the route group names `audit` and `automation` (B7 invariant 3). `audit.usage`, `audit.health`, `audit.notfound` and `audit.kpis` are actions of group `audit`, so no `jobs`, `channels` or `newsletter` scope is needed; the schedule row is a read of group `automation`. In both groups every write action excludes `commercial` (`audit.subject_export` and `audit.subject_delete` are admin and human only; B8b's puts are `chief_editor, media_ops, admin`), so the key can only read. It cannot change roles, keys, settings (architecture 6). It never uses the Supabase service role, the Meta token or the Resend key.
4. Deterministic first: everything a script can measure is a script in `workspace/audits/tools/` (zero tokens); the model only ranks, explains and writes patches.
5. Every number in the report exists in the JSON sidecar; the lint fails on a number in a table cell that is missing from the sidecar.
6. Free tier: the routine spends Claude usage only; no new paid API. PageSpeed, Search Console, GA4, Cloudflare analytics and the uptime monitor's free plan are free.
7. One threshold table (GS-06): `workspace/audits/tools/limits.json` is the only place the P-009 limits and the 50, 70 and 90 percent thresholds are written. `usage.mjs` reads it; `src/server/audit/gauges.ts` mirrors it for the daily `health` job, and `tests/unit/audit/gauges.test.ts` fails when the two differ. Vendor-side notifications are a second net, not the definition: Supabase and Cloudflare send their own emails at thresholds the vendor chooses (ASSUMED 80 and 100 percent, which is why our 70 percent line exists).
8. The 404 log stores no personal data: no IP, no user agent, no query string, referrer reduced to its host, at most 1,000 rows a day (a write cap protects the free database from a crawler loop). A 301 from `redirects` or `slug_history` is not a 404 and is not logged; the redirect map is B3's (`resolveRedirect` in `src/start.ts`, built from the `getCatalog` snapshot's `redirects` and `slug_history`, architecture 13 rule 1), never read from the table on each request, and it answers before the pipeline, so a redirected path never reaches the 404 hook. Writes stay cheap (rule 8): `logNotFound` adds to a per-isolate buffer, flushed as one multi-row insert at most every 10 seconds or when it holds 20 rows. The timer is a `waitUntil` promise, because a Worker runs nothing after the response unless one holds it: the first row into an empty buffer calls `ctx.waitUntil(delay(10_000).then(flush))`; a row that brings the buffer to 20 calls `ctx.waitUntil(flush())`; `flush` swaps the buffer out before the insert, so a second flush never sends the same rows. The daily cap is checked in memory first, and a failed flush (rejected insert or timeout) drops the rows, logs one `log.warn('not_found_flush_failed', { dropped })` and never fails the response; there is no retry. The hook sits after the cache lookup returns in B1b's pipeline (a hit or a render), so a 404 page served from the 60 second cache is counted too.
9. The robot never creates or edits the uptime monitor; the owner does, and `uptime.mjs` only reads it.
10. Every route this slice adds under `/api/admin/*` answers `Cache-Control: no-store` and is never put in the Cache API (rule 6); lists are paginated at 50 and the KPI and usage numbers come from indexed counts (rule 9). Nothing in this slice runs on a page view or calls an outside API there (rule 10).
11. The probe must not defeat the cache it measures: no cookie, no `Cache-Control: no-cache` request header, no query string on the measured pass.

Events emitted: none. Permissions: the agent account `mop-auditor` (kind `agent`, role `commercial`, scopes `audit` and `automation`, invariant 3), created on screen 23 by the admin; the key is shown once and stored only in the routine's environment. The four new actions `audit.usage`, `audit.health`, `audit.notfound`, `audit.kpis` are entries in B7's `src/server/lib/permissions/audit.ts` with roles `chief_editor`, `managing_editor`, `commercial`, `admin` (CE ME CO AD), and the same rows are added to B7's hand-typed fixture in `tests/unit/authz.matrix.test.ts`.
