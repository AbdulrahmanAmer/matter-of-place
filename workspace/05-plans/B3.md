## Goal and observed exit
Every path the `http` adapters already call exists under `/api/public/*`, validated by the same Zod file the forms use, cached where it is a catalog read, rate limited and bot checked where it is a write, with a request id in every log line and every error body (S8, S16, S17, S31, S35; architecture 4.1, 1, 8, 9; `docs/architecture/services.md` for the wire contract).
Observed exit (completion map B3): every form persists a row, and `services.mode === "live"` on the preview. Proved by `scripts/api-smoke.mjs` against a preview and by a parity test that compares the live catalog response with the bundled data the local adapter serves.

The rate limit numbers for inquiries, submissions, subscribers and events come from `services.md`; the per-email buckets, the confirm, search and concierge numbers are ASSUMED (architecture 9 asks for "per IP and per email" without values). DB-backed limits apply only to writes so reads and beacons cost no database write; memory limits are best effort per isolate and are backed by the Cloudflare rate-limit rule in HARDEN.

Error shape (extends `services.md`): `{ "error": { "code": string, "message": string, "issues"?: ZodIssue[], "requestId": string } }` plus header `x-request-id`. Codes: `bad_request` 400 (malformed JSON, wrong content type), `validation` 422 (schema), `forbidden` 403 (Turnstile), `not_found` 404, `method_not_allowed` 405 (with `Allow`), `payload_too_large` 413 (over 64 KB), `rate_limited` 429 (with `Retry-After`), `server` 500, `unavailable` 503 (database unreachable). The client maps 400 and 422 to "validation", 404 to "not-found", everything else to "server" (`src/services/http/client.ts`), and the visitor only ever sees the calm copy in `lib/strings.ts`.

Invariants
1. Handlers are thin: parse, call one service function, return JSON (architecture 2). No handler imports `@supabase/supabase-js`; only `src/server/lib/db.ts` does.
2. Every response carries `x-request-id`. Every request writes exactly one structured log line with `requestId`, `route`, `status`, `ms`, `ipHash`. Logs never contain an email address, a message body, a raw IP or a token.
3. Every write validates with the Zod schema first and the database constraints second. A schema failure never reaches the database.
4. IPs are never stored raw: `ip_hash = sha256(RATE_LIMIT_SALT + ":" + ip)` (matches `docs/database/schema.md` intent).
5. Public reads return `published` rows only, and never a row of a coming-soon market or, in production, an `Illustrative` row (`src/server/catalog/visibility.ts`; B3 ships a pass-through, B3b implements it).
6. Nothing external happens inside a request (architecture 1): no email, no post. Side effects are `emitEvent` calls.
7. The site and the API are same-origin, so `VITE_API_BASE_URL` is the relative `/api/public`. During SSR, loaders call the API in-process (no network hop) through an isomorphic fetch; in the browser they use `fetch`. ASSUMED: this avoids a Worker calling its own public URL, which double counts against the 100,000 requests a day and can be refused on shared hostnames. Proved in step 1.
8. The `services` contract, `src/services/types.ts`, does not change. Adapter files change only in transport (headers, fetch implementation).
9. Free tier only. No KV, no Queues, no Durable Objects (G-011).

Events emitted (through `src/server/lib/events.ts`, catalog of architecture 3.6): `inquiry.received` after an inquiry insert, `submission.received` after a submission insert, `subscriber.confirmed` after a confirmation click. Analytics beacons are rows in `analytics_events`, not events.
Permissions: anonymous callers only, plus the Svix signature for the Resend hook. No route reads a session. Admin routes are B7.

## Risks and gotchas (link GOTCHAS ids)
- G-005: routes import through `src/lib/queries.ts` and `services` only. Server code must not import `src/data/*` either; the bundled data reaches the server only in tests (parity test) and in `scripts/seed.ts`.
- G-006: `TURNSTILE_SECRET`, `SUPABASE_SERVICE_ROLE_KEY`, `RATE_LIMIT_SALT`, `RESEND_WEBHOOK_SECRET` are Worker secrets only. `VITE_TURNSTILE_SITE_KEY` is public and is the only new `VITE_*` name. Vite import protection (`vite.config.ts`, `**/server/**`) stops a client import of server code; step 1's grep proves it after the isomorphic fetch is added.
- G-004: `contracts.ts` changes (`markets`, media limits) and the SQL checks land in the same commit as their migration; `enums.check.ts` from B2 guards the enums.
- G-011 and P-009: Workers free is 100,000 requests a day; in-process API calls do not add requests. Supabase free egress is 5 GB a month; a full catalog response is under 100 KB and is cached, so a cache miss costs well under 1 MB an hour. The 10 ms CPU limit is the real risk: `toProperty` on 16 rows and Zod parses are small, SSR is the larger cost (B1b step 7). UNPROVEN until step 13.
- Cache API does nothing on `workers.dev` hostnames, so previews never cache; cache behaviour is proved at Stage 5 on the custom domain. Headers and the versioned key are still asserted now.
- Supabase's signed upload URL lifetime is fixed by Supabase (documented as 2 hours), not the 15 minutes `services.md` states. UNPROVEN, check in step 8 and correct the doc.
- `navigator.sendBeacon` with a JSON `Blob` sends `content-type: application/json` same-origin, so `POST /events` needs no CORS. It cannot carry the Turnstile header, which is why events are memory rate limited instead.
- The event catalog has no "confirmation requested" event, so the double opt-in email (B5) has no trigger. Options for B5 and B8: a system job `send_email:<subscriber_id>:1` enqueued by `enqueueJob` (B8 supports manual system jobs), or a spec change adding an event. `requestConfirmation` is the single place to wire it; until then subscribers stay unconfirmed and nothing is mailed. The raw token exists only in memory and, when wired, in the job payload.
- `emitEvent` is not in the same transaction as the insert until B8 moves it into the SQL functions. A crash between the two loses one event; the row is still there, so B7's queue shows it.
- Isolate memory limits reset on cold starts and differ per isolate. They stop accidents, not attackers; the Cloudflare rate-limit rule (HARDEN) and Turnstile do that.
- Same-origin `VITE_API_BASE_URL=/api/public` makes `siteConfig.apiBaseUrl` relative. Nothing else reads it as an absolute URL today (`grep -rn apiBaseUrl src`): only `services/index.ts` and `analytics.ts`. Re-run that grep at step 12.
- Cross-plan: B8 also lists `src/server/lib/events.ts` as a created file; B3 creates the stub first and B8 changes it. If the order flips, B3 skips the file and imports B8's.
